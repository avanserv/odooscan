# OD138 len-of-search

len() counts the result of search() where search_count() would count in the database.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Performance | Warning | all | no |

## What it reports

`len()` of a `search()` call on records with no `limit`, such as
`len(self.env["sale.order"].search(domain))`. Records are `self` in a model, `env[...]`, a call such
as `search()`, `filtered()` or `sudo()` on records, or a name bound to records, as [OD134](OD134.md)
describes. A `search()` on an attribute, such as a field or a compiled pattern held by the class, or
a call in a lambda is not reported.

## Why it matters

`search()` selects the id of every matching row and builds records of them (18.0 `odoo/models.py`,
20.0 `odoo/orm/models.py`, `search()`), all of which `len()` then drops. `search_count()` runs
`SELECT COUNT(*)` in the database and returns the number alone, and takes a `limit` when the code
only needs to know whether there are more than a few.

## Example

```python title="models/res_partner.py"
class ResPartner(models.Model):
    _inherit = "res.partner"

    def _x_has_many_orders(self):
        return len(self.env["sale.order"].search([("partner_id", "=", self.id)])) > 10
```

```python title="models/res_partner.py"
class ResPartner(models.Model):
    _inherit = "res.partner"

    def _x_has_many_orders(self):
        return self.env["sale.order"].search_count([("partner_id", "=", self.id)], limit=11) > 10
```

## Suppressing

```python
len(self.env["sale.order"].search(domain))  # odooscan: ignore[OD138]
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
