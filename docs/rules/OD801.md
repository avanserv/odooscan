# OD801 translation-placeholder-mismatch

A translation's placeholders differ from those of its message, so formatting it fails or loses a value.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Correctness | Warning | all | no |

## What it reports

An entry of a `.po` file in `i18n/` or `i18n_extra/` with a translation, a `code:` reference and
the `#. odoo-python` or `#. odoo-javascript` comment, whose translation does not fill the same
placeholders as its message. Odoo loads such an entry for `_()` in Python or `_t()` in the web
client. The message decides how both are read:

- Python, when a `%` of the message precedes something other than a space and one of its
  placeholders takes an argument, as `%` formatting: the translation is reported when Python cannot
  read one of its placeholders, or when it takes another number of arguments by position or another
  set of `%(key)s` keys. `10% off` is text.
- Python otherwise, when the message has `{}` fields, each named by an identifier, a number or
  nothing, as `str.format()`: the translation is reported when `str.format()` cannot read it, or
  when it takes other arguments. A `{}` field takes the next number, so `{} of {}` and `{1} de {0}`
  take the same ones.
- The web client, when the message has a `%s` or `%(key)s` placeholder, as its `sprintf()`: the
  translation is reported when it has another number of `%s` or another set of `%(key)s` keys.
  `%%` is text.

Keys and names may come in any order. A message without placeholders, or with `%%` alone, is not
checked: the code gives it no arguments, and without them neither `_()` nor `_t()` formats the
translation. An entry of a model field (`model:` or `model_terms:`) is not reported, nor is an empty
translation, which Odoo ignores. When the folder of the `.po` file holds the module's template,
such as `i18n/sale_kiosk.pot`, an entry the template lacks is not reported either: Odoo merges the
template into the catalog first and drops such an entry as obsolete.

The catalog does not tell whether a call gives arguments, so a message with a placeholder that the
code never formats, such as one that only describes `%s`, is checked like the others.

## Why it matters

`_()` formats the translation, and when that raises it logs the error and formats the source text
instead (18.0 `odoo/tools/translate.py:495-501`, 20.0 `:1011-1017`): every user of the language
reads the message untranslated. A translation that leaves out a key raises nothing and drops that
value. A message the code formats with `.format()` after `_()`, as 18.0
`addons/account/wizard/account_automatic_entry_wizard.py:541` does, raises a `KeyError` or
`IndexError` in the user's face, or shows another value when the code passes that name too. A
lone `%s` given the keys of a message raises nothing: it shows the whole mapping of arguments. The
web client's `sprintf()` fills a placeholder it has no value for with `undefined` (18.0
`addons/web/static/src/core/utils/strings.js:101`) or nothing (20.0 `:212`).

## Example

```po title="i18n/fr.po"
#. module: sale_kiosk
#. odoo-python
#: code:addons/sale_kiosk/models/sale_order.py:0
msgid "%(count)s orders are waiting"
msgstr "%(nombre)s ventes en attente"
```

```po title="i18n/fr.po"
#. module: sale_kiosk
#. odoo-python
#: code:addons/sale_kiosk/models/sale_order.py:0
msgid "%(count)s orders are waiting"
msgstr "%(count)s ventes en attente"
```

## Suppressing

A suppression comment covers the entry from anywhere among its comments, so it holds where
msgmerge and translation tools move a translator comment, at the top:

```po
# odooscan: ignore[OD801]
#. module: sale_kiosk
#. odoo-python
#: code:addons/sale_kiosk/models/sale_order.py:0
msgid "%(count)s orders are waiting"
msgstr "%(nombre)s ventes en attente"
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
