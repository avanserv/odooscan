# OD503 unknown-dependency

A module in depends is not on the addons path, or its manifest cannot be read.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Correctness | Error | all | yes |

## What it reports

An entry of the manifest's `depends` that names no module among those checked and those on the
addons path, or names one whose manifest cannot be read. A module whose manifest sets
`installable` to `False` does not count as present.

A dependency whose directory is on the addons path but whose manifest Odoo cannot read gets its
own message. Odoo creates no module record for it: 18.0 skips it in `update_list`
(`odoo/addons/base/models/ir_module.py:169-174`, `:809-811`), and 20.0 never lists it, since
`Manifest._from_path` returns `None` for a manifest that does not parse
(`odoo/modules/module.py:354-366`, `:379`). The dependency's state is then `unknown` (18.0
`ir_module.py:1037`, 20.0 `:1089`) and the install fails with the same error as for a missing
module (18.0 `ir_module.py:391-395`, 20.0 `:388-391`). A manifest that 9.0 or 10.0 reads but
odooscan cannot, as Python 2 or as an expression 9.0 evaluates, is reported as one odooscan cannot
read: the notice on that manifest says why, and [OD000](OD000.md) describes the forms.

## Why it matters

Odoo cannot install a module whose dependency it does not have: it refuses with `You try to
install module "x" that depends on module "y". But the latter module is not available in your
system.` The cause is a typo, a module renamed or merged into another in a new series, or a
module that lives in a repository the deployment does not include. When the message says the
dependency's manifest cannot be read, repair that manifest: the OD000 finding or the notice on it
says what is wrong.

A dependency on an Enterprise or third-party module is reported when that module's checkout is
not on `--addons-path`. Add the checkout rather than suppress the finding: without it, the rules
that need the index cannot see what the dependency defines, and most stay silent on what it could
add, in this module and in the modules that depend on it.

## Example

```python title="__manifest__.py"
{
    "name": "Rush delivery",
    "version": "18.0.1.0.0",
    "depends": [
        "sale_stock",
        "sales_management",
    ],
    "license": "LGPL-3",
}
```

No module is called `sales_management`, so Odoo refuses to install this one.

```python title="__manifest__.py"
{
    "name": "Rush delivery",
    "version": "18.0.1.0.0",
    "depends": [
        "sale_stock",
        "sale_management",
    ],
    "license": "LGPL-3",
}
```

## Suppressing

```python
"sales_management",  # odooscan: ignore[OD503]
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
