# OD503 unknown-dependency

A module in depends is not on the addons path, is not installable, or its manifest cannot be read.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Correctness | Error | all | yes |

## What it reports

An entry of the manifest's `depends` that names no module among those checked and those on the
addons path, or names one that is not installable or whose manifest cannot be read.

A dependency whose manifest sets `installable` to `False` gets its own message. Odoo records it
`uninstallable` (18.0 `odoo/addons/base/models/ir_module.py:812`, 20.0 `:835`), a state the
dependent's dependency row takes (18.0 `:1037`, 20.0 `:1089`). The install raises only on an
`unknown` dependency (18.0 `:391-396`, 20.0 `:388-396`), but the module graph then leaves the
dependent out, so it is never loaded (18.0 `odoo/modules/graph.py:85-104`, 20.0
`odoo/modules/module_graph.py:257-269`).

A dependency whose directory is on the addons path but whose manifest Odoo cannot read gets its own
message. Odoo creates no module record for it: 18.0 skips it in `update_list`
(`odoo/addons/base/models/ir_module.py:169-174`, `:809-811`), and 20.0 never lists it, since
`Manifest._from_path` returns `None` for a manifest that does not parse
(`odoo/modules/module.py:354-366`, `:379`). The dependency's state is then `unknown` (18.0
`odoo/addons/base/models/ir_module.py:1037`, 20.0 `:1089`) and the install fails with the same error
as for a missing module (18.0 `odoo/addons/base/models/ir_module.py:392-395`, 20.0 `:388-391`). A
dependency whose manifest the Odoo of the dependent's series reads but odooscan cannot, such as one
in Python 2 syntax on 9.0 or 10.0, gets no OD503: the notice on that manifest names it,
[OD000](OD000.md) describes the forms, and the rules that need the index treat the module as not
indexed. When that manifest sets `installable` to `False`, the dependency gets OD503 all the same.
A 10.0 module still gets OD503 on a Python 2 manifest only 9.0 evaluates, such as one holding
`'a' + 'b'`, since 10.0 reads the manifest with `ast.literal_eval`. Such a manifest is read as the
series of each module depending on it, whatever `--odoo-version` or its own version says, since
that module's Odoo is the one installing it.

## Why it matters

Odoo cannot install a module whose dependency it does not have: it refuses with `You try to
install module "x" that depends on module "y". But the latter module is not available in your
system.` The cause is a typo, a module renamed or merged into another in a new series, or a
module that lives in a repository the deployment does not include. When the message says the
dependency's manifest cannot be read, repair that manifest: the OD000 finding or the notice on it
says what is wrong.

A dependency that is not installable raises nothing: on 18.0 and 20.0 the install goes ahead, and
the module graph leaves the dependent out, so its code, views and data never load. When the
message says the dependency is not installable, drop it from `depends`, or port that module to the
series and make it installable.

A dependency on an Enterprise or third-party module is reported when that module's checkout is
not on `--addons-path`. Add the checkout rather than suppress the finding: without it, the rules
that need the index cannot see what the dependency defines, and most stay silent on what it could
add, in this module and in the modules that depend on it. A module that reaches the dependency
only through others gets no OD503; a notice names it instead, unless one of its own dependencies
is already not indexed.

## Example

```python title="__manifest__.py"
{
    "name": "Rush delivery",
    "version": "18.0.1.0.0",
    "depends": [
        "sale_stock",
        "sales_management",
    ],
    "license": "LGPL-3",
}
```

No module is called `sales_management`, so Odoo refuses to install this one.

```python title="__manifest__.py"
{
    "name": "Rush delivery",
    "version": "18.0.1.0.0",
    "depends": [
        "sale_stock",
        "sale_management",
    ],
    "license": "LGPL-3",
}
```

## Suppressing

```python
"sales_management",  # odooscan: ignore[OD503]
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
