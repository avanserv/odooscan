# OD209 model-redefined

A class redefines a model that a module in `depends` already defines.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Correctness | Error | all | yes |

## What it reports

A class that introduces a model one of the module's dependencies already defines, without naming
that model in `_inherit`: a class with `_name`, or one without it that Odoo names, as below. A
class without `_name` whose `_inherit` has an entry that is not a string literal is read as
extending its first literal entry, since the entries decide its name up to 18.0 and whether it is
new from saas~18.1. A module that Odoo always installs with `base`, such as `web`, counts as in
`depends`. Within the module itself, a second class that introduces the same model is reported when
it comes after the first in the same file; the order of separate files is that of the imports,
which the index does not record.

Setting `_inherit` to the same name, or `_inherit = _name`, extends the model and is not reported.
Neither is a model that only modules outside the dependencies define: two modules that do not
depend on each other may each be installed alone.

A class without `_name`, with no `_inherit` or with a list or tuple `_inherit`, gets a name too. Up
to 18.0, a one-entry list names the model the class extends, and no `_inherit` or any other list
gives the class name verbatim. From saas~18.1 the name is the class name, lowercased, with a dot
before each capital that is not its first character and does not follow `_`, so `ResPartner` names
`res.partner` whatever the list holds. From saas~18.1 a class whose `_name` is `False`, `None`, an
empty string or another literal that tests false is named this way too, whatever its `_inherit`.
From saas~14.4 to 18.0 such a `_name` stays. An empty string names the model, whose empty table name
then fails at install unless the model has no table, like an abstract one; any other value fails at
load. Before saas~14.4 Odoo reads it as no `_name`, so a single `_inherit` entry names the model and
anything else the class name verbatim.

Odoo names only the classes of its own model metaclass, and other libraries, such as peewee, call a
base class `Model` too, so the scan names a class after itself only when it is on a proven Odoo
base: a model class the file imports from `odoo` or `openerp` by an import that binds the name
before the class statement runs, or a model class of the file whose own base is such an import or
such a class. The import is at module level, outside any function or class, alone or in any block
there, such as an `if`, a `try`, a loop or a `match`. For a class at module level, or in a class
body there, it must be above the class, as Python runs the statement once, when the module runs. For
a class in a function the scan counts an import anywhere at module level, taking the function to run
after the module has, which a call at module level above the import would not. Before saas~14.4 Odoo
reads `_name` and `_inherit` through the bases, so then, and when the series is unknown, the scan
gives no name to a class with no `_name` and no `_inherit` or an empty one whose base is a model
class of its file, or a class of its file that binds `_name` or `_inherit` or derives from one that
does. [Series](https://avanserv.github.io/odooscan/series/) says how a module of unknown series
reads these classes.

## Why it matters

Odoo treats a class whose `_name` is not among its `_inherit` as the definition of a new model.
Odoo builds a fresh model from a class that defines one, the parents its `_inherit` names and
`base`, and puts it in the registry in place of the existing one, so every field and method the
earlier modules gave the model is gone. Their views and related fields that use a lost field then
fail to load, their code fails when it reaches one, and the database columns behind the lost fields
are left without a field.

## Example

```python title="models/product_template.py"
class ProductTemplate(models.Model):
    _name = "product.template"
    _description = "Product"

    warranty_months = fields.Integer()
```

`product` already defines `product.template`, so this class replaces the model instead of adding a
field to it.

```python title="models/product_template.py"
class ProductTemplate(models.Model):
    _inherit = "product.template"

    warranty_months = fields.Integer()
```

## Suppressing

```python
class ProductTemplate(models.Model):  # odooscan: ignore[OD209]
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
