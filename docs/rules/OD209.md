# OD209 model-redefined

A new `_name` replaces a model that a module in `depends` already defines.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Correctness | Error | all | yes |

## What it reports

A class that sets `_name` to a model one of the module's dependencies already defines, without
naming that model in `_inherit`. Within the module itself, a second class with the same `_name` is
reported when it comes after the first in the same file; the order of separate files is that of
the imports, which the index does not record.

## Why it matters

Odoo treats a class whose `_name` is not among its `_inherit` as the definition of a new model. It
builds a fresh model from that class, the parents its `_inherit` names and `base`, and puts it in
the registry in place of the existing one, so every field and method the earlier modules gave the
model is gone. Their views and related fields that use a lost field then fail to load, their code
fails when it reaches one, and the database columns behind the lost fields are left without a field.

Setting `_inherit` to the same name, or `_inherit = _name`, extends the model and is not reported.
Neither is a model that only modules outside the dependencies define: two modules that do not
depend on each other may each be installed alone.

## Example

```python title="models/product_template.py"
class ProductTemplate(models.Model):
    _name = "product.template"
    _description = "Product"

    warranty_months = fields.Integer()
```

`product` already defines `product.template`, so this class replaces the model instead of adding a
field to it.

```python title="models/product_template.py"
class ProductTemplate(models.Model):
    _inherit = "product.template"

    warranty_months = fields.Integer()
```

## Suppressing

```python
class ProductTemplate(models.Model):  # odooscan: ignore[OD209]
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
