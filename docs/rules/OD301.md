# OD301 unresolved-xmlid

The XML id is not defined by its module.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Correctness | Error | all | yes |

## What it reports

A reference to an XML id that its module, which the referencing module does depend on, never
defines. A module that Odoo always installs with `base`, such as `web`, counts as in `depends`. In
data files the references checked are `ref` attributes, `ref()` in `eval`, `inherit_id`, a menu's
`parent` and `action`, `groups`, and `%(id)d` in view attributes. In Python they are `env.ref()` and
the groups given to `has_group()` or a field's `groups`. An id without a module prefix names one of
the module's own.

## Why it matters

Odoo resolves each reference in a data file while it loads the file, and an id that is not there
stops the install with "External ID not found in the system". In Python, `env.ref()` raises
`ValueError` when the line runs, which can be long after the install, on the one path a test did
not cover. The usual cause is a typo, or an id that the other module renamed or removed in a new
series.

The rule leaves alone what Odoo itself tolerates: `ref('x', False)` and
`env.ref('x', raise_if_not_found=False)`, an empty `ref=""`, and an id built at runtime. It counts
as defined the `model_*` and `field_*` ids Odoo creates for every model and field, and ids that
`_update_xmlids` assigns. It skips data files the manifest does not load, upgrade scripts under
`migrations/` and `upgrades/`, ids of a module that is in `depends` but not indexed, such as an
Enterprise one, and in Python every id of a module that is not indexed.

## Example

```xml title="views/sale_order_views.xml"
<record id="view_order_form_customer_ref" model="ir.ui.view">
    <field name="name">sale.order.form.customer.ref</field>
    <field name="model">sale.order</field>
    <field name="inherit_id" ref="sale.view_order_from"/>
    <field name="arch" type="xml">
        <field name="payment_term_id" position="after">
            <field name="client_order_ref"/>
        </field>
    </field>
</record>
```

`sale` defines `view_order_form`, not `view_order_from`, so the install stops at this record.

```xml title="views/sale_order_views.xml"
<record id="view_order_form_customer_ref" model="ir.ui.view">
    <field name="name">sale.order.form.customer.ref</field>
    <field name="model">sale.order</field>
    <field name="inherit_id" ref="sale.view_order_form"/>
    <field name="arch" type="xml">
        <field name="payment_term_id" position="after">
            <field name="client_order_ref"/>
        </field>
    </field>
</record>
```
