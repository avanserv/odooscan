# OD322 unknown-selection-value

A data record gives a Selection field a value it does not list.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Correctness | Error | all | yes |

## What it reports

The text of a `<field>`, a whole string `eval`, or a CSV cell, written to a Selection field, when no
definition of that field in any indexed module lists the value in a literal `selection` or
`selection_add`. A field of an `_inherits` parent counts as a field of the child, unless the child
has its own.

The value is compared as written, spaces included, because Odoo does not trim it either. A CSV cell
also passes as a label, or as a value or label in another case, since the import looks both up.

## Why it matters

Odoo validates a list selection on write, so the file raises `ValueError: Wrong value for ...` and
stops the install or the update of the module. The usual causes are a value renamed in Python and
missed in the data, a typo, and a label written where the value belongs.

The union over every indexed module is deliberate. A value another module adds with `selection_add`
loads first when that module is auto-installed, so only a value no module lists is certain to fail.

The rule stays silent where only a run tells the values:

- A selection given by a method, a lambda or a variable, or with `int` keys.
- A tuple as `selection` below 19.0, which Odoo does not validate, and in an unknown series.
- A field with `validate=False`, a related field, a field that is not stored, and a field that
  unpacks `**kwargs`.
- A `selection_add` whose base no indexed definition lists.
- A `search`, a `ref`, a `type`, a `file`, a `name@lang` field, a bigger `eval`, and an empty value,
  which clears the field. Only the last `<field>` of a name counts.
- The inverse field of a record nested in a one2many, and a record nested in any other type of field.
- A value a later write replaces in the module's scope. A value only a module outside the scope
  replaces still reports, since a database without that module keeps it.
- A file the manifest does not load.
- A module with a dependency that is not indexed, a module that builds model names at runtime, and a
  model with a parent the scan cannot see.

## Example

```python title="models/res_partner.py"
class ResPartner(models.Model):
    _inherit = "res.partner"

    tier = fields.Selection([("gold", "Gold"), ("silver", "Silver")])
```

```xml title="data/res_partner.xml"
<odoo>
    <record id="partner_shop" model="res.partner">
        <field name="name">Shop</field>
        <field name="tier">Gold</field>
    </record>
</odoo>
```

`Gold` is the label, and `tier` stores `gold`.

```xml title="data/res_partner.xml"
<odoo>
    <record id="partner_shop" model="res.partner">
        <field name="name">Shop</field>
        <field name="tier">gold</field>
    </record>
</odoo>
```

The value is one the field lists.

```xml
<!-- odooscan: ignore[OD322] -->
```
