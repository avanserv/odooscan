# OD517 test-file-not-imported

A test file is never imported by the tests package, so Odoo never runs its tests.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Quality | Warning | all | no |

## What it reports

A `test_*.py` file directly under `tests/` that no chain of imports reaches from
`tests/__init__.py`, from the module's root `__init__.py` or from another module. The finding is on
the file's first line. An import under any name binds the file, so `from . import test_loans as
loans` reaches it. Files in subpackages of `tests/` are left out.

Nothing is reported for a module without a root `__init__.py`, one with a Python file the scan
cannot decode, or when an import on the way computes the name of what it imports, loads a file by
its path or does not parse.

## Why it matters

Odoo runs the tests of the submodules the `tests` package binds under a name starting with
`test_`, which only an import does. A test file left out of `tests/__init__.py` never runs, and
the test run passes without it, so whatever it was written to catch goes unchecked.

## Example

```python title="tests/__init__.py"
from . import test_book
```

`tests/test_loan.py` holds the loan tests, but nothing imports it, so they never run.

```python title="tests/__init__.py"
from . import test_book
from . import test_loan
```

## Suppressing

The finding is on the file's first line, so a trailing comment there covers it:

```python
from odoo.tests import TransactionCase  # odooscan: ignore[OD517]
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
