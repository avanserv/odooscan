# OD134 search-in-loop

A search runs on each pass of a loop over records where one search for them all would do.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Performance | Info | all | no |

## What it reports

A call to `search()` or `search_count()` in the body of a `for` loop over records, on a model the
loop does not vary, such as `self.env["sale.order.line"]`, in two forms:

- no argument names a name the loop binds, so every pass runs the same query;
- the call gives no `limit` and no argument but the domain names what the loop binds, its domain
  is a literal list of `(field, operator, value)` terms and `"&"`, `"|"` or `"!"`, with a literal
  field and operator in each term, and the value of one term alone names what the loop binds, in a
  term whose operator is `=` or `in` on a field of the model rather than a dotted path. The message
  names the field of that term.

A loop is over records when it iterates over `self` in a model, `env[...]`, a field of records, a
call such as `search()`, `filtered()`, `sorted()` or `sudo()` on records, or a name bound to any of
them. A loop over ids, strings or `mapped()` is not, and a comprehension or a `while` loop is not
itself a loop over records, though a search in one inside a loop over records is reported. A name
the loop binds is its target, a name assigned anywhere in its body, or a name the body changes in
place, by setting an item of it or calling a method such as `append()` or `update()` on it. Records
changed in place keep their model. A name the body assigns once, and nowhere before the loop, of a
value that names nothing else the loop binds, such as
`field = self.env["ir.model.fields"].search(...)`, has the same value on each pass and counts as
fixed in a search or a `browse()`.

It stays silent on a search:

- whose model names what the loop binds, such as `self.env[rec.res_model]`;
- whose model is an attribute, such as a field of records or a class constant like a compiled
  pattern;
- keyed on a record with a `limit`, with another argument that names what the loop binds, such as
  `order=rec.order`, through a domain built in a name, by an operator such as `child_of`, `!=` or
  `<`, on a dotted path, or by more than one value the loop binds, which one search grouped by a
  field cannot answer for each record;
- whose result goes to a cache: to a name bound before the loop when its arguments name nothing the
  loop binds, or, whatever its arguments, to a name bound before the loop or an item such as
  `cache[key]` inside an `if` whose test names that name or `cache`;
- in a `try` statement or a `with ...savepoint()` block inside the loop, which handles each record's
  failure on its own;
- in a block that ends with `break`, `return` or `raise`, which runs at most once each time the loop
  starts;
- in a function, a class or a lambda the loop holds.

## Why it matters

Each `search()` and `search_count()` is a SQL query (18.0 `odoo/models.py`, 20.0
`odoo/orm/models.py`, `search_count()` and `search()`). A loop over a thousand records runs a
thousand of them, where one query with the field `in` the ids, or one `_read_group()` grouped by the
field, returns the same answer at the cost of one. A search whose arguments never change returns the
same records on each pass, so running it once before the loop saves every query after the first.

## Example

```python title="models/sale_order.py"
class SaleOrder(models.Model):
    _inherit = "sale.order"

    def _compute_x_line_count(self):
        for order in self:
            order.x_line_count = self.env["sale.order.line"].search_count([("order_id", "=", order.id)])
```

```python title="models/sale_order.py"
class SaleOrder(models.Model):
    _inherit = "sale.order"

    def _compute_x_line_count(self):
        counts = dict(
            self.env["sale.order.line"]._read_group([("order_id", "in", self.ids)], ["order_id"], ["__count"])
        )
        for order in self:
            order.x_line_count = counts.get(order, 0)
```

## Suppressing

```python
self.env["sale.order.line"].search_count([("order_id", "=", order.id)])  # odooscan: ignore[OD134]
```
