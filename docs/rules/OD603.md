# OD603 unknown-rpc-model

An ORM call from JS names a model no indexed module defines.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Correctness | Error | all | yes |

## What it reports

A call of the `orm` service, such as `this.orm.call()`, `searchRead()`, `read()` or `write()`,
whose first argument is a literal model name that no indexed module defines, or that only a
module missing from `depends` defines. The service is recognised as `orm`, `something.orm`, and
either one through `.silent` or `.cache(...)`. A module that Odoo always installs with `base`,
such as `web`, counts as in `depends`.

The legacy calls `something._rpc({...})`, from 11.0, and `rpc.query({...})` are read the same way
when their object gives both a `model` and a `method`, since Odoo then sends them to the model's
method. An object that also gives a `route`, spreads another object or has a computed key may
send the call elsewhere, so it is skipped.

## Why it matters

The server looks the model up when the request arrives and answers with an error the user sees
as a dialog, every time the call runs. A model of a module that is not in `depends` exists only
where that module happens to be installed. The usual cause is a typo, or a model renamed or
removed upstream between series.

The rule skips a model built at runtime, such as `this.props.resModel`. In a module whose Python
code outside `tests/`, `tests.py`, `examples/`, `migrations/` and `upgrades/` builds model names at
runtime, it skips any model no indexed module defines. In any module, a model that the module, a
module in its `depends` or an always-installed module may build is skipped too, whether no indexed
module defines it or only a module missing from `depends` does, since Odoo builds each module's
models as it loads, ahead of the modules that depend on it. That is a name that fits an expression
the same code builds `_name` from, where an expression that shows no literal start fits every name,
or the name a class may take in a module of unknown series, as
[Series](https://avanserv.github.io/odooscan/series/) describes. A fit to every name counts only in
the module's own code. For this rule, `base` builds only names that start with `x_`, whatever its
code shows. A user may create any `x_` model in the database, so a missing `x_` model is never
reported, a misspelt one included. The rule reads the scripts a bundle loads, both ES modules and
those written with `odoo.define()`, as [OD601](OD601.md) describes, but not
[test scripts](index.md#od6-javascript-and-owl), which run on a mock server.

The rule stays silent on a model that a dependency that is not indexed, such as an Enterprise
module, could load. A model the module defines whole is in scope, so the rule never reports one. Add
the checkout of the dependency that is not indexed to `--addons-path` to check the other models.

## Example

```js title="static/src/js/company_list.js"
const companies = await this.orm.searchRead("res.partners", [["is_company", "=", true]], ["name"]);
```

The model is `res.partner`.

```js title="static/src/js/company_list.js"
const companies = await this.orm.searchRead("res.partner", [["is_company", "=", true]], ["name"]);
```

## Suppressing

```js
// odooscan: ignore[OD603]
const companies = await this.orm.searchRead("res.partners", [["is_company", "=", true]], ["name"]);
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
