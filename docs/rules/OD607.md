# OD607 private-rpc-method

An ORM call from JS names a private method, which Odoo refuses to call over RPC.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Correctness | Error | all | no |

## What it reports

A call `orm.call(model, method, ...)`, or a legacy `_rpc({model, method})` or
`rpc.query({model, method})`, whose method is a literal Odoo refuses over RPC:

- a name starting with `_`, whatever the model;
- a method `BaseModel` makes private in the module's series, whatever the model, as listed in
  [OD313](OD313.md#what-it-reports): `init` from 10.0, and from 16.0 names such as `ensure_one`,
  `concat` and `union`, but for saas~16.1 to 16.4 and saas~17.1 to 17.3;
- with a literal model, `get_all` from saas~19.4 when a class in scope of the model, or of a model
  it inherits, is on `CachedModel`, and a method any such class decorates with `@api.private`.

The model may be an expression such as `this.props.resModel`, which leaves the first two. Of the
names `BaseModel` and `CachedModel` make private, a module of unknown series is reported only for
`init`, which nearly every series refuses: saas~19.1 to saas~19.3 accept `get_all`. The calls are
recognised as for [OD603](OD603.md), through `orm.silent` and `orm.cache()` too, in every script a
bundle loads but [test scripts](index.md#od6-javascript-and-owl).

## Why it matters

The server refuses to dispatch a method whose name starts with `_`, or one that any class of the
model's MRO decorates with `@api.private`, and answers with an `AccessError` the user sees as a
dialog, every time the call runs, even when the model has it. From 10.0 `init` is refused by name
until `@api.private` takes over. Such a method is meant for Python callers only. The usual cause
is a client calling the helper behind a public method, or a record helper such as `ensure_one`,
rather than the public method or a new one the module adds to wrap it.

[OD604](OD604.md) leaves these calls to this rule, so a private method the model does not have
is reported once, here.

## Example

```js title="static/src/js/post_button.js"
await this.orm.call("account.move", "_post", [[this.props.record.resId]]);
```

`_post` is the helper behind posting an entry: the method the client may call is `action_post`.

```js title="static/src/js/post_button.js"
await this.orm.call("account.move", "action_post", [[this.props.record.resId]]);
```

## Suppressing

```js
// odooscan: ignore[OD607]
await this.orm.call("account.move", "_post", [[this.props.record.resId]]);
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
