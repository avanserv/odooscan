# OD608 cross-bundle-js-import

A JS import names a module the bundles of the importer's page do not load.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Correctness | Error | 18.0 and later | yes |

## What it reports

An `import` or `export ... from` in a script that a web client page loads, whose target file is in
some bundle but in none that page loads. The backend page loads `web.assets_web`, which includes
`web.assets_backend`. The frontend page loads `web.assets_frontend_minimal` and
`web.assets_frontend_lazy`, which includes `web.assets_frontend`. The finding names the bundles
that hold the target, three at most, and the bundle of the page that holds the importer.

## Why it matters

Each page starts the modules of its own bundles, and the module loader starts a module only once
every module it imports is defined. On the page that lacks the target, the browser console reports
the target as not present in the correct asset bundle, and the importer, with every module that
imports it, as never started. In debug mode the page also shows a red banner that points to the
console; otherwise nothing looks wrong until a feature of one of those modules is used.

A script in no page bundle, such as one of a bundle code loads lazily, is not checked: it joins a
page that already holds other bundles, and the scan cannot tell which. A target in no bundle is not
reported either, since an `ir.asset` record may load it. An import the scan reports under
[OD601](OD601.md), of a missing file, of a module missing from `depends` or of a name the target
does not export, is not reported here. Nor is any import of a module whose dependencies reach one
the scan did not index, such as an Enterprise one, since that one may add the target to the page.

## Example

```python title="__manifest__.py"
{
    "name": "Shop banner",
    "version": "18.0.1.0.0",
    "depends": ["web"],
    "assets": {
        "web.assets_backend": ["shop_banner/static/src/backend/**/*"],
        "web.assets_frontend": ["shop_banner/static/src/frontend/**/*"],
    },
    "license": "LGPL-3",
}
```

```js title="static/src/backend/banner_field.js"
import { bannerText } from "@shop_banner/frontend/banner";
```

`banner.js` is only in `web.assets_frontend`, so the backend page never starts `banner_field.js`.
Move what both pages use to a file both bundles list.

```python title="__manifest__.py"
{
    "name": "Shop banner",
    "version": "18.0.1.0.0",
    "depends": ["web"],
    "assets": {
        "web.assets_backend": [
            "shop_banner/static/src/shared/**/*",
            "shop_banner/static/src/backend/**/*",
        ],
        "web.assets_frontend": [
            "shop_banner/static/src/shared/**/*",
            "shop_banner/static/src/frontend/**/*",
        ],
    },
    "license": "LGPL-3",
}
```

```js title="static/src/backend/banner_field.js"
import { bannerText } from "@shop_banner/shared/banner";
```

## Suppressing

```js
// odooscan: ignore[OD608]
import { bannerText } from "@shop_banner/frontend/banner";
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
