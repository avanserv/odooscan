# OD613 owl1-api-removed

A script uses an Owl 1 API that Owl 2 removed: `hooks`, `tags`, `QWeb` or a component's `trigger()`.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Deprecation | Error | saas~15.3 and later | yes |

## What it reports

In every script a bundle loads but those under `static/tests`:

- `owl.hooks`, `owl.tags` and `owl.QWeb`, once for a chain such as `owl.hooks.useState`.
- `hooks`, `tags` or `QWeb` destructured from the `owl` global, as in
  `const { hooks, QWeb: Q } = owl`, or imported from `@odoo/owl`.
- `this.trigger()` in a component: a class whose chain of parents ends at Owl's `Component`,
  extended as `owl.Component`, through a name imported from `@odoo/owl`, or one destructured from
  `owl`. Calls in its methods, accessors and field values count, arrow functions in them included;
  a static member, a nested `function` or class has another `this` and does not.

The parents are followed through imports and re-exports, as for [OD602](OD602.md). A component is
silent when it, a parent or a patch of them has a `trigger` member, as 16.0's `LegacyComponent`
has. It is silent too when a parent cannot be resolved, such as one from `require()` in an
`odoo.define()` script, and when the module's dependencies include one that is not indexed (such
as an Enterprise module, which may patch the class).

## Why it matters

Odoo moves from Owl 1 to Owl 2 in saas~15.3. Owl 2 exports its hooks and `xml` directly, and has
no `hooks`, `tags` or `QWeb` namespace, so code that reads one gets `undefined` and throws as soon
as it uses it. Its `Component` has no `trigger()` method either: Owl 1 components told their
parent about an event by triggering a DOM event, while Owl 2 components call a function their
parent passes in props, or use the environment's bus. 16.0 keeps `LegacyComponent`, an Owl 2
component with `trigger()`, for the legacy views; 17.0 removes it.

## Example

```js title="static/src/js/rating_widget.js"
/** @odoo-module **/
const { Component } = owl;
const { useState } = owl.hooks;

export class RatingWidget extends Component {
    setup() {
        this.state = useState({ value: 0 });
    }

    onClick(value) {
        this.state.value = value;
        this.trigger("rating-changed", { value });
    }
}
```

```js title="static/src/js/rating_widget.js"
/** @odoo-module **/
import { Component, useState } from "@odoo/owl";

export class RatingWidget extends Component {
    static props = { onChange: Function };

    setup() {
        this.state = useState({ value: 0 });
    }

    onClick(value) {
        this.state.value = value;
        this.props.onChange(value);
    }
}
```

The parent passes `onChange` in its template, as `<RatingWidget onChange.bind="onRatingChanged"/>`.

## Suppressing

```js
this.trigger("rating-changed", { value }); // odooscan: ignore[OD613]
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
