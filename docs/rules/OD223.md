# OD223 compute-leaves-field-unassigned

A compute method leaves a non-stored readonly field unassigned on some records.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Correctness | Error | 14.0 and later | yes |

## What it reports

A compute method with a path through its loop over `self` that ends an iteration without assigning a
field it computes, when Odoo neither stores the field nor lets users write it. Odoo merges every
definition of the field in the module and its `depends`, so the merged one decides: `store` is
absent or false, `readonly` is true, or absent with no `inverse`, and the field is not `related`. A
module that Odoo always installs with `base`, such as `web`, counts as in `depends`. An attribute
that definitions set differently, or that `**kwargs` may set, leaves the field unchecked. The
finding is at the method's name, and names each such field.

The method must be in the class that defines the field and hold every assignment of the field in
its one `for record in self:` loop, each on that record. A method that calls `super()`, reads the
field, may assign it by a name built at runtime (`setattr`, a key that is not a literal, or
`update()` or `write()` given something other than a dict of literal keys), or calls a method of
`self` or passes `self` on outside the loop is not checked. Through the loop body:

- an assignment, `update()` or `write()` of the field, a `raise`, and a call of a method of the
  record or of `self`, or a call given the record, which may assign the field in a helper, count as
  assigning it;
- a `continue`, `break` or `return` before that is reported, and so is an `if` without `else` whose
  test is false, but a chain with an `elif` and no `else`, like a `match`, is taken to cover every
  case, and so are two statements that each assign the field on some paths, as `if x:` and
  `if not x:` do;
- a `try` assigns when its body and `else` do and so does each handler, or when its `finally` does;
- a nested loop may run no iteration, so its `else` counts, and only when every `break` in its body
  assigns first; a `while True:` loop counts when its body assigns before every `break`.

## Why it matters

When code reads a computed field, Odoo calls its method on the records to compute, then looks for
those it left without a value. Odoo raises `ValueError: Compute method failed to assign` for a
field it neither stores nor lets users write, so the form, list or report that reads the field
fails for the records the method skipped, often only for some data. Other computed fields get
`False` silently. Assign the field on every path of the loop, with `False` when there is no value.

## Example

```python title="models/res_partner.py"
class ResPartner(models.Model):
    _inherit = "res.partner"

    initials = fields.Char(compute="_compute_initials")

    @api.depends("name")
    def _compute_initials(self):
        for partner in self:
            if partner.name:
                partner.initials = "".join(word[0] for word in partner.name.split())
```

A partner without a name, such as a new address in a form, makes reading `initials` raise.

```python title="models/res_partner.py"
class ResPartner(models.Model):
    _inherit = "res.partner"

    initials = fields.Char(compute="_compute_initials")

    @api.depends("name")
    def _compute_initials(self):
        for partner in self:
            if partner.name:
                partner.initials = "".join(word[0] for word in partner.name.split())
            else:
                partner.initials = False
```

## Suppressing

```python
def _compute_initials(self):  # odooscan: ignore[OD223]
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
