# OD610 html-sink

A script sets a value built at runtime as the HTML of an element.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Security | Info | all | no |

## What it reports

An assignment, `=` or `+=`, to the `innerHTML` or `outerHTML` of an element, and a call `x.html(v)`,
whose value is not a constant, in every script a bundle loads but those under `static/tests`. A
constant is a string, a template whose every `${}` holds a constant, `+` of constants, a
conditional `c ? a : b` between two constants, or `_t()` of constants. Reading `innerHTML`, calling
`html()` without an argument, and `html(v)` on a name starting with a capital, a library such as
`Diff2Html` whose `html()` returns a string, are not reported. This is a
hotspot: code to review, not a confirmed flaw.

## Why it matters

The browser parses the value as HTML, so markup in it becomes elements and an `onerror` or
`onclick` attribute in it runs as script, with the session of the user viewing the page
(cross-site scripting). jQuery's `html(v)` sets the `innerHTML` of each element it holds. When any
part of the value comes from a record or a user, the finding asks for it to be escaped, or for the
text to be set with `textContent` or jQuery's `text()`. The `web` of 20.0 ships no jQuery, but a
module may bring its own.

## Example

```js title="static/src/js/partner_card.js"
renderName(name) {
    this.el.querySelector(".o_partner_name").innerHTML = name;
    this.$(".o_partner_city").html(this.city);
}
```

A partner named `<img src=x onerror=alert(1)>` runs the script for whoever opens the card.

```js title="static/src/js/partner_card.js"
renderName(name) {
    this.el.querySelector(".o_partner_name").textContent = name;
    this.$(".o_partner_city").text(this.city);
}
```

Both set the values as text, which the browser never parses as HTML.

## Suppressing

```js
// odooscan: ignore[OD610]
this.el.innerHTML = this.props.record.data.body_html;
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
