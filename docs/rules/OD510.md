# OD510 depends-on-itself

The module lists itself in depends, so Odoo never loads it.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Correctness | Error | all | no |

## What it reports

An entry of the manifest's `depends` that names the module itself. It is the shortest
[circular dependency](OD504.md), which is not reported again at the same entry.

## Why it matters

Odoo loads a module once every module in its `depends` is loaded. A module waiting on itself is
never ready: Odoo logs `Unmet dependencies` and leaves it out, so its models, views and data are
missing. The entry usually comes from a copied manifest, or a module renamed to the name of one it
depended on.

## Example

```python title="library_loan/__manifest__.py"
{
    "name": "Library loans",
    "version": "18.0.1.0.0",
    "depends": ["base", "library_loan"],
    "license": "LGPL-3",
}
```

Remove the entry:

```python title="library_loan/__manifest__.py"
{
    "name": "Library loans",
    "version": "18.0.1.0.0",
    "depends": ["base"],
    "license": "LGPL-3",
}
```

## Suppressing

```python
"depends": ["base", "library_loan"],  # odooscan: ignore[OD510]
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
