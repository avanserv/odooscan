# OD109 private-env-shortcut

`self._cr`, `self._uid` and `self._context` are deprecated; use `self.env`.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Deprecation | Warning | 19.0 and later | no |

## What it reports

Each use of `self._cr`, `self._uid` or `self._context` in a model class, in a module of series
19.0 or later. A model class is one with a model base, such as `models.Model` or a model class
earlier in the file, or one that names its model with a literal `_name` or `_inherit`; a method's
inner function counts as part of it. A class on a base imported from a file of a scanned module,
such as `class Partner(ResPartner)` after `from .partner import ResPartner`, is one when that file
defines `ResPartner` on a model base, but a class that names no model and is built on `Partner`,
in its file or another, is not checked. A plain class, a class nested in a model, a class on a base
the scan cannot find and a module-level function are not checked either, since their `self` need
not be a recordset.

## Why it matters

The three attributes are shortcuts for `self.env.cr`, `self.env.uid` and `self.env.context`. Odoo
19.0 deprecated them: they still return the same values, but each access emits a
`DeprecationWarning`. Odoo removes deprecated names in a later series, as 20.0 did with the
`group_operator` field attribute ([OD108](OD108.md)), and code that still uses one then raises
`AttributeError`.

Modules of earlier series are not checked. Only the attributes read on `self` are reported, not on
another recordset such as `partner._context`.

## Example

```python title="models/stock_picking.py"
class StockPicking(models.Model):
    _inherit = "stock.picking"

    def _lock_for_dispatch(self):
        self._cr.execute("SELECT id FROM stock_picking WHERE id IN %s FOR UPDATE", [tuple(self.ids)])
        return self.with_context(dispatched_by=self._uid)
```

Both `self._cr` and `self._uid` warn on every call from 19.0.

```python title="models/stock_picking.py"
class StockPicking(models.Model):
    _inherit = "stock.picking"

    def _lock_for_dispatch(self):
        self.env.cr.execute("SELECT id FROM stock_picking WHERE id IN %s FOR UPDATE", [tuple(self.ids)])
        return self.with_context(dispatched_by=self.env.uid)
```

## Fixing

`oscn check --fix` rewrites each reported read of `self._cr`, `self._uid` or `self._context` to
`self.env.cr`, `self.env.uid` or `self.env.context`. An assignment or a `del` is reported but left
as it is, since it sets a different attribute than the one `self.env` exposes.

See [fixing findings](https://avanserv.github.io/odooscan/fixing/).

## Suppressing

```python
lang = self._context.get("lang")  # odooscan: ignore[OD109]
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
