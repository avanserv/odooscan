# OD521 unused-dependency

The module uses nothing of a module in depends, nor of what only that one brings.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Quality | Info | all | yes |

## What it reports

An entry of the manifest's `depends` from which the module takes nothing. What the entry brings
is the entry itself and each module it depends on, directly or through others, that no other entry
brings and that Odoo does not install on every database, as it does `base` and `web`. The module
takes from those when a word of its manifest, of its Python, XML and CSV files, or of the scripts
and templates under `static/` outside the third-party `static/lib`, tests and comments included, is:

- a model one of them introduces with `_name`, or the table of one;
- a field, method or `selection_add` value one of them defines on a model it introduces, when no
  other module the module may use defines that name on any model, its own aside;
- a field or `selection_add` value one of them adds to a model of another module, when no such
  module defines that name on that model;
- a method one of them adds to or overrides on a model of another module, since the override may
  be what makes a call do anything. A method every model has, such as `create`, and a compute,
  inverse, search or onchange method count only when no other module the module may use defines
  that name on any model;
- a QWeb view or template one of them defines;
- a URL path a controller of one of them routes, as `/shop` or `/shop/cart` in a link;
- the name of one of them joined to others with `.` or `/`, as an XML id (`sale.menu_sale`), a
  Python import (`odoo.addons.sale`), a JS module (`@sale/...` or `@sale/../lib/x`), an asset bundle
  or an asset path writes it. The name alone, as `depends` itself writes it, is no use.

An inherited view or template of the module also takes from them when one of its specs locates an
element only they add to the tree it extends, such as `//block[@id='user_default_rights']`. When
a view on the way to the root of that tree sits in a file that does not parse, is not indexed, or
writes its arch to a field the scan does not read (`arch_base`), the spec counts as a use.

Words carry no model, so a name one of them gives on another model than the one the module
means still counts: the rule stays silent on such an entry rather than report one in use.

The rule leaves out `base`, which an empty `depends` stands for from saas~18.2, and the entries
OD503, OD504 and OD520 report, as well as one with a dependency off the addons path, which may hold
the use. It is silent on a module with `auto_install`, a bridge that exists to pull its
dependencies in, on one with no file but its manifest and `__init__.py`, and on one with a file
the scan cannot read as text.

## Why it matters

Odoo installs a dependency, and what it depends on, on every database that installs the module,
and loads the module after it. A dependency the module does not use installs modules nobody
asked for and ties the module to them.

## Example

```python title="__manifest__.py"
{
    "name": "Partner notes",
    "version": "18.0.1.0.0",
    "depends": ["sale"],
    "license": "LGPL-3",
}
```

```python title="models/res_partner.py"
from odoo import fields, models


class ResPartner(models.Model):
    _inherit = "res.partner"

    note_text = fields.Text()
```

The module adds a field to a model of `base` and uses nothing of `sale`, so it depends on `base`
alone.

```python title="__manifest__.py"
{
    "name": "Partner notes",
    "version": "18.0.1.0.0",
    "depends": ["base"],
    "license": "LGPL-3",
}
```

## Suppressing

Keep an entry on purpose, such as one whose install the module relies on without naming anything
of it (`base_geolocalize`, which fills the `partner_latitude` of `base` the module reads, or
`base_vat`, whose constraint checks the VAT numbers), by suppressing the finding on it:

```python
"depends": ["sale"],  # odooscan: ignore[OD521]
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
