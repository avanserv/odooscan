# OD519 unresolved-python-import

A Python import names a module or a name the target module does not have.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Correctness | Error | all | yes |

## What it reports

An import of a module by its path under `odoo.addons` or `openerp.addons`, or by a relative path
that climbs past the importing module's root, that names something the indexed module lacks: a
package or a Python file no path of the module has, or, after `from`, a name the module it imports
from neither binds at import nor has as a submodule. A missing path is reported on the module path,
a missing name on the name. Names of the form `__name__` always count.

A name counts as bound when the file assigns it, defines it with `def` or `class`, or imports it,
at the top of the file or in an `if`, `try`, `with`, loop or `match` block there, and when a
function of the file declares it `global` or an assignment expression binds it. Nothing is
reported against a file that may bind names out of the scan's sight: through a star import, a
module `__getattr__`, `globals()`, `locals()`, `vars()`, `exec()`, `eval()`, `sys.modules`, a
frame's `f_globals` or `f_locals`, or a function's `__globals__`.

The rule leaves out an import in a `try` that catches `ImportError` or `ModuleNotFoundError`, under
`contextlib.suppress()` or `if TYPE_CHECKING:`, and any in a file under `migrations/` or
`upgrades/`. It stays silent on a module that is not indexed, one with a file it cannot decode or a
file on the way that does not parse, on `base.maintenance`, which Odoo maps to `odoo.upgrade`, and
on `tests/` of a module whose `tests/` is not there, as when the scan reads a core fetched by
`--target-series`.

## Why it matters

Python raises `ModuleNotFoundError` or `ImportError` when the import runs. At the top of a file
Odoo imports as the module loads, that stops the module loading, and with it the server's start or
the install; in a function, the call fails. The usual cause is a file moved or a class renamed in
the other module between series.

## Example

```python title="models/sale_order.py"
from odoo.addons.sale.models.sale_orders import SaleOrder
```

`sale` has `models/sale_order.py`, so no file provides `odoo.addons.sale.models.sale_orders`.

```python title="models/sale_order.py"
from odoo.addons.sale.models.sale_order import SaleOrder
```

## Suppressing

```python
from odoo.addons.sale.models.sale_orders import SaleOrder  # odooscan: ignore[OD519]
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
