# OD407 rule-field-without-index

A record rule or ir.access domain filters reads on a stored field without an index.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Performance | Info | all | yes |

## What it reports

Each field of a model's own table that the literal domain of a record rule filters on, once per
field, at the domain, when the field has no index. Before saas~19.4 the rule is an `ir.rule`, in XML
or CSV; from saas~19.4 it is an `ir.access` record, and in a module of unknown series either.

A term counts when its path is dotted, whatever its operator, or when its field is plain and its
operator is `=`, `=?`, `in`, `<`, `<=`, `>`, `>=`, `child_of`, `parent_of` or `any`. A dotted
path or an `any` counts only when its first field is a Many2one, and is reported on that field.
The field must be stored, not company-dependent, which Odoo indexes by default, and a Many2one,
Many2oneReference, Integer, Float, Monetary, Char, Date, Datetime or Reference, with `index` unset,
`False`, `None`, `0` or `''`. A translated field is left alone, as Odoo skips its btree (18.0
`odoo/modules/registry.py:625-659`), and so is a related Char that sets no `translate` unless its
target is known and not translated, as it takes the target's.

A multi-company term such as `('company_id', 'in', company_ids)` or
`('company_id', 'parent_of', company_ids)` counts like any other, since Odoo gives a Many2one to
`res.company` no index of its own and turns a hierarchy term on a Many2one to another model into an
`IN` on the column (18.0 `odoo/osv/expression.py:950-951,1364-1365`, 20.0
`odoo/orm/domains.py:1869`).

The rule is read as every write the scope loads leaves it, whichever module makes it. It is reported
at the write that gives its last domain, when the rule is active and applies to reads.

Not reported:

- a domain built at runtime, such as one joined with `+`, or one that holds `'!'`;
- a rule whose `perm_read` is false, or an `ir.access` record whose operation lacks `r`, as Odoo
  checks those on fetched ids in Python (18.0 `odoo/models.py:4494-4497`);
- a model that is abstract, transient, sets `_auto = False`, gives a `_table_query` or
  `_table_sql`, or defines or inherits `init()`, which may create the index by hand;
- a field named by an SQL constraint or a `models.Index` of the model, or of a model it inherits,
  that Odoo applies in the module's series and no later definition of its name replaces;
- a dotted path or an `any` on a Many2one that sets `auto_join`, `bypass_search_access` or
  `delegate`, or that `_inherits` names, as Odoo joins the comodel there instead;
- a `parent_of` term on a Many2one to the model itself, as Odoo reads the field to walk up (18.0
  `odoo/osv/expression.py:947`);
- a `child_of` term on a Many2one to the model itself, when the `_parent_store` the model sets or
  inherits last is true, as Odoo matches `parent_path` instead (18.0 `odoo/osv/expression.py:889-896`):
  on any such Many2one before saas~18.1, then only on the `_parent_name` field, `parent_id` by
  default (20.0 `odoo/orm/domains.py:1874`);
- a Many2one whose comodel only a run can tell, such as one a constant names;
- a model with a class the scan cannot read, one whose parent is outside the scan or whose file
  does not parse, as that class may give the field or its index;
- a field the model gets through `_inherits`, and the magic fields such as `create_uid`.

## Why it matters

Odoo adds the domain of every read rule that applies to the user to the `WHERE` clause of each
search on the model (18.0 `odoo/models.py:5597-5609`, 20.0 `odoo/orm/models.py:4885-4893`). A
condition on a column without an index makes PostgreSQL scan the whole table for each list view,
each `search()` and each count, by every user the rule restricts. A dotted path becomes an `IN` on
the column (18.0 `odoo/osv/expression.py:1164-1167`), which the index serves the same way.

## Example

```python title="models/support_ticket.py"
class SupportTicket(models.Model):
    _name = "support.ticket"
    _description = "Support ticket"

    team_id = fields.Many2one("support.team")
```

```xml title="security/rules.xml"
<record id="rule_support_ticket_team" model="ir.rule">
    <field name="name">Tickets of my teams</field>
    <field name="model_id" ref="model_support_ticket"/>
    <field name="domain_force">[('team_id', 'in', user.x_team_ids.ids)]</field>
</record>
```

```python title="models/support_ticket.py"
class SupportTicket(models.Model):
    _name = "support.ticket"
    _description = "Support ticket"

    team_id = fields.Many2one("support.team", index=True)
```

## Suppressing

```xml
<!-- odooscan: ignore[OD407] -->
```

For a CSV row, where a comment would break the file, pass `--ignore OD407` or record the finding
in a [baseline](https://avanserv.github.io/odooscan/baseline/).

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
