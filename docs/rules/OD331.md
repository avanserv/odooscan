# OD331 unknown-client-action

A client action's tag names an action no script registers.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Correctness | Error | 17.0 and later | yes |

## What it reports

The `tag` an `ir.actions.client` record of a loaded data file writes as text, when no script of the
modules in scope adds it to `registry.category("actions")`. Odoo stores the text as written, spaces
included. A key counts when a loaded script outside `static/tests` adds it as a string literal,
through `registry.category("actions").add("x", ...)`, a chain of `.add()` on it, or a binding of
the category. A tag that only a module missing from `depends` registers is reported too, naming
that module. A module that Odoo always installs with `base`, such as `web`, or auto-installs with
the module, counts as in `depends`.

Modules before 17.0 are not checked: up to saas~16.4 a client action may sit in the legacy action
registry, which the web client bridges to this one.

## Why it matters

The web client looks the tag up when it runs the action and throws `Cannot find key "x" in the
"actions" registry`, so the menu or button that opens it fails. Client actions are renamed or moved
to other modules between series, which leaves the record pointing at nothing after a port.

The rule stays silent for a module whose dependencies include one that is not indexed, such as an
Enterprise module, and when a script in scope adds a key to the action registry that only a run
tells, as a lazy loader given the tag as an argument does. A tag that Python code returns in a
dictionary is not read.

## Example

```xml title="data/actions.xml"
<record id="action_board" model="ir.actions.client">
    <field name="name">Board</field>
    <field name="tag">sale_board.board</field>
</record>
```

```js title="static/src/board.js"
registry.category("actions").add("sale_board.dashboard", Board);
```

The script registers the action under `sale_board.dashboard`.

```xml title="data/actions.xml"
<record id="action_board" model="ir.actions.client">
    <field name="name">Board</field>
    <field name="tag">sale_board.dashboard</field>
</record>
```

## Suppressing

```xml
<!-- odooscan: ignore[OD331] -->
<field name="tag">sale_board.board</field>
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
