# OD602 orphan-patch-super

A patch calls a super method the class it patches does not have.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Correctness | Error | saas~14.5 and later | yes |

## What it reports

A call that reaches the patched member when neither the class nor any class it extends has a
method, accessor or field of that name, and no other patch of those classes adds one. The class is
followed through imports and re-exports to the file that declares it, and ends at Owl's
`Component` when it extends one imported from `@odoo/owl`, `owl.Component`, or a `Component`
destructured from the `owl` global, as in `const { Component } = owl`. That `Component` counts as
having `setup` and `render` from saas~15.3, where Odoo moves to Owl 2, and every member of Owl 1's
`Component`, such as `mounted` and `willStart`, before it. An import from `@odoo/owl` is Owl 2 in
any series, as only Owl 2 ships that module. The `owl` global takes the series of the module
declaring the class, else of the module checked, since core's `web` gives `'version': '1.0'`. The
form of the patch depends on the series:

- From 17.0, `patch(Class.prototype, {...})`, and a `super.name()` call in its methods.
- From saas~14.5, where `@web/core/utils/patch` appears, to 16.0, the named
  `patch(Class.prototype, "patch name", {...})`, and a `this._super()`, `this._super.apply()` or
  `this._super.call()` call in its methods, which reaches the member of the method's name. An
  arrow function in the method is read with it, while a nested `function` or class has its own
  `this` and is not.

A patch of the other form is not read: 17.0 and later throw on a name, 15.0 and 16.0 throw without
one, and saas~14.5 applies nothing without one. A module of unknown series has both read.

## Why it matters

`patch` makes `super` in the patch's methods point at the class's own member, or the previous
patch's. When there is none, `super.name` is `undefined` and the call throws a `TypeError` the
first time the patched method runs. A named patch binds `this._super` only when the class has the
member, so otherwise `this._super` is whatever the object already holds: `undefined`, which
throws, or the super of an enclosing patched method, which runs the wrong method. The usual cause
is a method renamed or removed upstream between series: the override no longer overrides
anything, and it breaks as soon as it is called.

The rule stays silent when it cannot see every parent: a class extending an expression such as a
mixin call, or a class from a module that is not indexed or not a script, such as an Owl class
other than `Component`, and a module whose dependencies include one that is not indexed (such as
an Enterprise module, which may patch the class too). A read such as `super.name || fallback` is
not reported, since it tolerates a missing member. A patch in a script written with
`odoo.define()` is not read, since its classes come through `require`.

## Example

```js title="static/src/js/form_controller_patch.js"
import { patch } from "@web/core/utils/patch";
import { FormController } from "@web/views/form/form_controller";

patch(FormController.prototype, {
    async onRecordSave(record, changes) {
        await super.onRecordSave(...arguments);
        this.notification.add("Saved");
    },
});
```

`FormController` names this method `onRecordSaved`, so the patch adds a method nobody calls, and
calling it fails.

```js title="static/src/js/form_controller_patch.js"
import { patch } from "@web/core/utils/patch";
import { FormController } from "@web/views/form/form_controller";

patch(FormController.prototype, {
    async onRecordSaved(record, changes) {
        await super.onRecordSaved(...arguments);
        this.notification.add("Saved");
    },
});
```

Before 17.0 the patch is named and reaches the method through `this._super`. 16.0 names the
method `saveButtonClicked`, so this patch fails the same way:

```js title="static/src/js/form_controller_patch.js"
/** @odoo-module **/
import { patch } from "@web/core/utils/patch";
import { FormController } from "@web/views/form/form_controller";

patch(FormController.prototype, "my_module.FormController", {
    async saveButtonClick(params) {
        await this._super(...arguments);
        this.notification.add("Saved");
    },
});
```

Renaming its method to `saveButtonClicked` fixes it.

## Suppressing

```js
await super.onRecordSave(...arguments); // odooscan: ignore[OD602]
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
