# OD612 debugger-statement

A script a page loads has a `debugger` statement.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Quality | Warning | all | no |

## What it reports

A `debugger` statement in every script a bundle loads but those under `static/tests`. A statement
ESLint is told to accept, as it reads its comments, is not reported: an
`// eslint-disable-next-line no-debugger` on the line before, as the tours of `web_tour` use to
pause a step on request, an `// eslint-disable-line no-debugger` on the line of the statement, or a
statement between `/* eslint-disable no-debugger */` and `/* eslint-enable no-debugger */` or the
end of the file. A comment that names no rule covers every rule, this one included.

## Why it matters

`debugger` stops the script in every browser that has its developer tools open, so a user or a
support engineer who opens them sees the page freeze on a line of the module with no explanation.
It is a debugging leftover, and Odoo's own ESLint configuration refuses it with an error.

## Example

```js title="static/src/js/order_line.js"
onQuantityChange(quantity) {
    debugger;
    this.props.record.update({ product_uom_qty: quantity });
}
```

```js title="static/src/js/order_line.js"
onQuantityChange(quantity) {
    this.props.record.update({ product_uom_qty: quantity });
}
```

## Suppressing

```js
if (this.debug) {
    // eslint-disable-next-line no-debugger
    debugger;
}
```

ESLint's own comment silences the finding too, or else `// odooscan: ignore[OD612]` on the line
before.

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
