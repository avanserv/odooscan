# OD715 sudo-domain-injection

Data a user controls picks the fields of a domain or a grouping searched as superuser.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Security | Error | all | no |

## What it reports

A value from a [source](https://avanserv.github.io/odooscan/rules/#od7-data-flows) that reaches,
on records under `sudo()`, the domain of `search()`, `search_count()`, `search_read()` and
`search_fetch()`, the fields the last two read, or the domain, fields, `groupby` and `aggregates`
of `read_group()`, `_read_group()` and `formatted_read_group()`, by position or keyword.
[What runs as superuser](https://avanserv.github.io/odooscan/rules/#od7-data-flows) lists the
forms besides `sudo()`.

A condition whose field and operator the code picks holds the user to its value and is not
reported: a tuple or a list of three items, or `Domain(field, operator, value)`, such as
`("name", "ilike", term)`. In a tuple or `Domain()` any name may stand for the operator; in a list
only one after a field written as a string or f-string, so `[active, mine, term]` is read as three
conditions, or as three domains inside a join, and is reported. The list that
`expression.AND()`, `Domain.OR()` or an `AND()` or `OR()` imported from `odoo.osv.expression`
joins holds domains, and the fields `search_read()` and `search_fetch()` read are names, so
neither is ever a condition. An operator written as a string holds the user to the value only
when it compares a value, such as `=`, `ilike` or `in`, and a condition with any other is reported:
among them `any` and `not any`, which take a domain, and `any!` and `not any!` from 19.0. A test
that a field is in `_fields` proves only that it exists. In the arm of
`if field in ("name", "email"):` the field is one the code chose and is not reported; after the
`if` it is.

Domains combined with `&`, `|` or `~` keep the user's side, as `expression.AND()` and `OR()` do:
`active & Domain(filters)` is reported, and `active & Domain("name", "ilike", name)` is not. `|`
always keeps both sides. `&` is read as a join of domains, rather than an intersection that keeps
only the values the code chose, and `~` keeps its operand's taint, only when an operand is written
as `Domain(...)`, an attribute or method of `Domain` such as `Domain.TRUE` or `Domain.AND()`, or a
`&`, `|` or `~` of these.

## Why it matters

`sudo()` lifts the access rights, the record rules and the groups of each field. A domain the user
writes may then filter on any field, even one the route never returns: a search that finds a
record or not tells the user one character of a cost price, a token or a password hash at a time.
The fields or the grouping the user picks are read outright.

## Example

```python title="controllers/main.py"
class Stock(http.Controller):
    @http.route("/shop/stock", type="json", auth="public")
    def stock(self, domain):
        return request.env["product.product"].sudo().search_count(domain)
```

`domain` may be `[("standard_price", ">", 100)]`, which tells a public visitor the cost price of a
product, one count at a time.

```python title="controllers/main.py"
class Stock(http.Controller):
    @http.route("/shop/stock", type="json", auth="public")
    def stock(self, name):
        return request.env["product.product"].sudo().search_count([("name", "ilike", name)])
```

## Suppressing

```python
products = request.env["product.product"].sudo().search(domain)  # odooscan: ignore[OD715]
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
