# OD404 public-secret-field

A field named as a secret has no groups, on a model public or portal users can read.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Security | Warning | all | yes |

## What it reports

A stored `fields.Char` or `fields.Text` without `groups` whose name ends in `password`, `token`,
`secret` or `api_key`, such as `webhook_secret` or `maps_api_key`, on a model an access row lets
public or portal users read. That row is one the modules in scope load, outside demo data, that
gives `perm_read` to `base.group_portal`, to `base.group_public`, from saas~19.1 to
`base.group_everyone`, or on `ir.model.access` to no group, which is every user. From saas~19.4 it
is an `ir.access` row whose `operation` holds `r` for one of those groups.

The module that introduces the field reports it there, once an access row in its scope opens the
model. When a later module adds the row instead, or extends a field of another module, the module
with the row reports it at its first such row, unless another module in its scope already has one.

Not reported: `access_token`, which portal links carry and the portal user who follows one may
read; a field of `res.users`, whose secrets Odoo hides from other users
(18.0 `odoo/addons/base/models/res_users.py:580-585`); a related field, one that is not stored,
one of a `TransientModel` or of a mixin; and a field on a model whose access rows are written in
XML, or name their group by database id.

## Why it matters

A portal user can call `read()` and `search_read()` over JSON-RPC on any model their access rows
allow, and get every field without `groups` of the records the record rules let through, whether
or not a view shows it. A token, a password or an API key stored there is theirs to read. Give the
field a group portal users are not in, such as `base.group_system`, and read it under `sudo()` in
the code that needs it.

## Example

```python title="models/shipping_carrier.py"
class ShippingCarrier(models.Model):
    _name = "shipping.carrier"
    _description = "Shipping carrier"

    name = fields.Char()
    tracking_api_key = fields.Char()
```

```csv title="security/ir.model.access.csv"
id,name,model_id:id,group_id:id,perm_read,perm_write,perm_create,perm_unlink
access_shipping_carrier_portal,shipping.carrier portal,model_shipping_carrier,base.group_portal,1,0,0,0
```

```python title="models/shipping_carrier.py"
class ShippingCarrier(models.Model):
    _name = "shipping.carrier"
    _description = "Shipping carrier"

    name = fields.Char()
    tracking_api_key = fields.Char(groups="base.group_system")
```

## Suppressing

```python
tracking_api_key = fields.Char()  # odooscan: ignore[OD404]
```

At an access row, where a comment would break the CSV file, pass `--ignore OD404` or record the
finding in a [baseline](https://avanserv.github.io/odooscan/baseline/).

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
