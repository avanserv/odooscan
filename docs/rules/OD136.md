# OD136 create-in-loop

A loop over records creates one record per pass where one create() of a list would do.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Performance | Info | all | no |

## What it reports

A call to `create()` in the body of a `for` loop over records, on a model the loop does not vary,
with the values of one record: a dict literal, a `dict()` call, or a name last bound to one of them.
The call's result must be dropped, or added to a collection with `|=`, `+=` or `.append()`, so that
the records one call returns would serve as well. The loop, its records and the cases it stays
silent on are those of [OD134](OD134.md), except a keyed search and a result that goes to a cache,
which concern a search alone.

A `create()` whose result the pass uses, such as `line = ...create({...})`, or given a list or the
result of a call, is not reported.

## Why it matters

`create()` takes a list of values and inserts them with one `INSERT` per hundred records (18.0
`odoo/models.py`, 20.0 `odoo/orm/models.py`, `_create()`), and marks the fields that depend on them
to recompute once for the batch. A call per record runs that whole path per record: an insert, and
the recomputations, each time.

## Example

```python title="models/sale_order.py"
class SaleOrder(models.Model):
    _inherit = "sale.order"

    def _x_log_confirmation(self):
        for order in self:
            self.env["x.order.log"].create({"order_id": order.id, "event": "confirmed"})
```

```python title="models/sale_order.py"
class SaleOrder(models.Model):
    _inherit = "sale.order"

    def _x_log_confirmation(self):
        self.env["x.order.log"].create([{"order_id": order.id, "event": "confirmed"} for order in self])
```

## Suppressing

```python
self.env["x.order.log"].create({"order_id": order.id})  # odooscan: ignore[OD136]
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
