# OD515 migration-script-refused

A migration script lacks the migrate(cr, version) Odoo calls, so the update fails.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Correctness | Error | 18.0 and later | no |

## What it reports

A `pre-`, `post-` or `end-` script of a folder under `migrations/` or `upgrades/`, `tests` aside,
that:

- binds no `migrate`, on its first line;
- defines `migrate` with parameters other than two positional ones, `cr` or `_cr` then `version`
  or `_version`, on the `def`. Defaults are taken; a third parameter, `*args`, `**kwargs` or a
  keyword-only parameter is not.

Only an undecorated `def migrate` at the top of the file is judged. A `migrate` that is imported,
assigned, defined under `if` or decorated is not reported, nor is a file with a star import, a
module `__getattr__`, or one that does not parse.

## Why it matters

Odoo imports each script of a folder it runs and checks `migrate` before calling it with the
cursor and the installed version. A missing `migrate` raises `AttributeError` and another
signature `TypeError`. Nothing catches either, so the update of the module stops there. The usual
cause is a script written like a hook, which takes `env` from 17.0.

## Example

```python title="migrations/18.0.1.1.0/post-migrate.py"
from odoo import SUPERUSER_ID, api


def migrate(env, version):
    env["library.loan"].search([("state", "=", False)]).write({"state": "draft"})
```

Take the cursor, and build the environment from it:

```python title="migrations/18.0.1.1.0/post-migrate.py"
from odoo import SUPERUSER_ID, api


def migrate(cr, version):
    env = api.Environment(cr, SUPERUSER_ID, {})
    env["library.loan"].search([("state", "=", False)]).write({"state": "draft"})
```

## Suppressing

```python
def migrate(env, version):  # odooscan: ignore[OD515]
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
