# OD502 data-file-not-loaded

A data file is not listed in the manifest, so Odoo never loads it.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Quality | Warning | all | no |

## What it reports

An XML data file, one whose root is `<odoo>`, `<openerp>` or `<data>`, or a CSV file, in a
subdirectory of the module, that the manifest lists in neither `data` nor `demo`.

## Why it matters

Odoo loads only the files the manifest lists. Views, menus, access rows and records in any other
file never reach the database, without an error or a warning: the module installs, and the
screen or the access it was meant to add is simply not there. The cause is usually a new file
not added to the manifest, or a file renamed on disk but not in the list, which
[OD501](OD501.md) then reports too.

Files that are not meant for the manifest are left alone: those under `tests/`, `i18n/`,
`migrations/`, `upgrades/`, `doc/`, `docs/` and `examples/`, those at the module root, chart
templates under `data/template/`, and any file whose name appears in the module's Python code,
which loads it itself. XML whose root is anything else, such as a QWeb `<templates>` file, is not
a data file.

## Example

```python title="__manifest__.py"
{
    "name": "Library loans",
    "version": "18.0.1.0.0",
    "depends": ["base"],
    "data": ["security/ir.model.access.csv"],
}
```

The module ships `views/library_loan_views.xml`, but nothing loads it, so the loans have no list
view.

```python title="__manifest__.py"
{
    "name": "Library loans",
    "version": "18.0.1.0.0",
    "depends": ["base"],
    "data": [
        "security/ir.model.access.csv",
        "views/library_loan_views.xml",
    ],
}
```

## Suppressing

The finding is on the file's first line, so in XML a trailing comment there covers it:

```xml
<odoo> <!-- odooscan: ignore[OD502] -->
```

For a CSV file, pass `--ignore OD502`, add it to `ignore` in the configuration file, or list the
file in `exclude`.

See [suppressing a finding](https://github.com/avanserv/odooscan#suppressing-a-finding).
