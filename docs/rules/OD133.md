# OD133 translation-arguments-mismatch

The arguments of _() or_lt() do not fit the placeholders of its message, so formatting it raises or prints them wrong.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Correctness | Error | all | no |

## What it reports

A call to `_()` or `_lt()` whose message is a literal and which gives arguments to fill it, when:

- it gives both positional and keyword arguments;
- a placeholder of the message is one Python's `%` cannot read, such as `%)` or a key followed by no
  conversion, as in `%(name))`;
- it gives positional arguments to a message with a `%(key)s` placeholder, or not as many as its
  placeholders take, a `*` width or precision taking one more;
- it gives keyword arguments to a message with a placeholder without a key, or none for a key the
  message names.

The `_module=` and `_default_lang=` of `_lt()` are not arguments of the message. A keyword
argument that no placeholder names is not reported, since Python ignores the unused keys of a
mapping. A call that unpacks arguments with `*` or `**` is not reported, nor is a call without
arguments, whose message is not formatted.

## Why it matters

`_()` formats the translation with the arguments, and when that fails it formats the source text
instead, outside of any `try` (`odoo/tools/translate.py`, `get_translation()`). A source text its
arguments do not fit raises `TypeError`, `ValueError` or `KeyError` in every language, so the user
gets a server error in place of the message, often the error message the code meant to show.
Keyword arguments given to a message with a single placeholder without a key do not raise: that
placeholder shows them all as a Python dict. Positional and keyword arguments together fail an
assertion before any formatting, and `_lt()` asserts it when it is called; the formatting of
`_lt()` raises only when its text is used.

## Example

```python title="models/sale_order.py"
from odoo import _, models
from odoo.exceptions import UserError


class SaleOrder(models.Model):
    _inherit = "sale.order"

    def action_check_partner(self):
        if not self.partner_id.email:
            raise UserError(_("%s ordered %s without an email", self.partner_id.name))
```

The message takes two arguments and gets one, so the user sees a `TypeError` instead.

```python title="models/sale_order.py"
from odoo import _, models
from odoo.exceptions import UserError


class SaleOrder(models.Model):
    _inherit = "sale.order"

    def action_check_partner(self):
        if not self.partner_id.email:
            raise UserError(
                _(
                    "%(partner)s ordered %(order)s without an email",
                    partner=self.partner_id.name,
                    order=self.name,
                )
            )
```

## Suppressing

```python
message = _("%s ordered %s", name)  # odooscan: ignore[OD133]
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
