# OD333 csv-data-dropped

A data CSV loses data without a message: a cell past its header, or a quote never closed.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Correctness | Warning | 11.0 and later | no |

## What it reports

A CSV file the manifest loads, in `data` or `demo`, where Odoo's import loses data without an error:

- a row with a cell past the columns of the header that holds anything, at that cell;
- a quote that opens a cell in a row below the header and is never closed, at the quote.

Each file reports once, at the first such row from the top; a quote never closed comes before a
cell past the header in its row, since it is the cause. A cell past the header that is empty, or
`""`, loses nothing and is not reported, nor is a quote inside an unquoted cell such as `12"`,
which the reader keeps as a character. A blank first line is the header, with no columns, so the
first row under it reports. A quote never closed in the header is not reported: the header then
holds a line break, which the import refuses as a field name, stopping the install.

A file the import refuses reports [OD000](OD000.md) alone, as an unclosed quote does when it ends
its row before a relational column. Modules before 11.0 are not checked, nor a module of unknown
series, as for every rule with a series range.

## Why it matters

The import reads each row against the header and drops the cells past it, without an error or a
line in the log. Such a cell is most often a comma inside a value that is not quoted: the value is
cut at the comma, the rest moves into the next column, and the last cell of the row is lost.

Python's `csv` reader takes a quote that is never closed as a cell that runs to the end of the
file, line breaks included. The rows below it then load as text in that one cell, not as records,
unless the field refuses the text, which stops the install.

## Example

```csv title="data/res.partner.csv"
id,name,city
partner_brussels,Brussels office,Brussels, Belgium
```

The comma splits the city: `city` gets `Brussels`, and `Belgium` is dropped.

```csv title="data/res.partner.csv"
id,name,city
partner_brussels,Brussels office,"Brussels, Belgium"
```

A quote that is never closed takes the rows below it:

```csv title="data/res.partner.csv"
id,name,street
partner_ghent,Ghent office,"Korenmarkt 1
partner_liege,Liège office,Place Saint-Lambert 2
```

The Ghent office's street holds both lines, and the Liège office is never created.

```csv title="data/res.partner.csv"
id,name,street
partner_ghent,Ghent office,Korenmarkt 1
partner_liege,Liège office,Place Saint-Lambert 2
```

## Suppressing

A comment would break the CSV file, so pass `--ignore OD333` or add it to `ignore` in the
configuration file. To keep one reviewed file without turning the rule off, record it in a
[baseline](https://avanserv.github.io/odooscan/baseline/).

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
