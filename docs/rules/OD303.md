# OD303 duplicate-xmlid

The same XML id is defined twice in one file.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Correctness | Warning | all | no |

## What it reports

A record, template, menu or CSV row whose id an earlier element of the same data file already
defines. Records nested in a One2many field count, since Odoo gives them their own ids.

## Why it matters

Odoo does not complain. The second definition finds the record the first one created and writes
its values over it, so the file yields one record where its author meant two, with the fields of
both definitions mixed. Anything that referred to the first one now points at a record that has
changed under it. The cause is almost always a copied block whose id was not renamed.

Ids that a `<function model="ir.model.data" name="_update_xmlids">` call assigns are not
definitions, so a record that later sets the same id is not reported: it is meant to update the
record. The rule compares ids within one file; an id defined in two files of the module is left
alone.

## Example

```xml title="data/res_partner_category_data.xml"
<record id="tag_wholesale" model="res.partner.category">
    <field name="name">Wholesale</field>
</record>
<record id="tag_wholesale" model="res.partner.category">
    <field name="name">Retail</field>
</record>
```

The second record renames the first, and the database ends up with a single tag called Retail.

```xml title="data/res_partner_category_data.xml"
<record id="tag_wholesale" model="res.partner.category">
    <field name="name">Wholesale</field>
</record>
<record id="tag_retail" model="res.partner.category">
    <field name="name">Retail</field>
</record>
```

## Suppressing

```xml
<!-- odooscan: ignore[OD303] -->
```

See [suppressing a finding](https://github.com/avanserv/odooscan#suppressing-a-finding).
