# OD308 xmlid-used-before-definition

An XML id is referenced before the file that defines it is loaded.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Correctness | Error | all | no |

## What it reports

A reference in a data file to one of the module's own XML ids that is defined further down the
same file, or in a file the manifest lists later in `data` or `demo`. Data files load in manifest
order, and each file from top to bottom.

## Why it matters

Odoo resolves a reference at the moment it reads it, so an id defined later does not exist yet,
and a fresh install stops with "External ID not found in the system". An update of a module that
is already installed passes, because the id is left over from the previous install. The mistake
therefore survives every test run on an existing database and surfaces the first time someone
installs the module on a new one.

The `model_*` and `field_*` ids of the module's own models are not reported: Odoo creates them
when it loads the models, before any data file. Neither are references in `base`, whose bootstrap
records exist before its data files load. Ids of other modules are checked by [OD301](OD301.md)
and [OD302](OD302.md), and files the manifest does not list are left to [OD502](OD502.md).

## Example

```xml title="views/res_partner_category_views.xml"
<menuitem id="menu_partner_segments"
          parent="contacts.res_partner_menu_config"
          action="action_partner_segments"/>
<record id="action_partner_segments" model="ir.actions.act_window">
    <field name="name">Segments</field>
    <field name="res_model">res.partner.category</field>
</record>
```

The menu names the action one record before the action exists.

```xml title="views/res_partner_category_views.xml"
<record id="action_partner_segments" model="ir.actions.act_window">
    <field name="name">Segments</field>
    <field name="res_model">res.partner.category</field>
</record>
<menuitem id="menu_partner_segments"
          parent="contacts.res_partner_menu_config"
          action="action_partner_segments"/>
```

When the definition is in another file, move that file before this one in the manifest's `data`.
