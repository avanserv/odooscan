# OD232 route-override-undecorated

An override of a route method has no @route(), so Odoo drops the route or, from saas~15.3, warns.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Correctness | Error, Info from saas~15.3 | all | yes |

## What it reports

A method of a controller with no decorator at all, whose name a class it inherits, in the module or
in any indexed module, decorates with `@route()`. The class must be a controller: one of its bases
the scan reads comes from `odoo.http.Controller`. The finding sits on the method's `def` and names
the class whose route it overrides.

## Why it matters

Odoo merges the routing of a method with the routes of the methods it overrides, but only the
decorated definitions take part. Through saas~15.2 Odoo routes only a method whose definition in
the controller it builds carries a route, so an override without `@route()` takes the path out of
the routing map: requests to it get a 404. From saas~15.3 Odoo decorates such an override itself
and logs `The endpoint ... is not decorated by @route(), decorating it myself.` each time it builds
the routing map, so the route works and the finding is Info. A module of unknown series gets the
Error.

The rule leaves out a method with another decorator, which may stand for the route or wrap it, and
the controllers of `tests/`, `migrations/` and `upgrades/`. It passes over a base the scan does not
read, such as one a relative import or a library names, since Odoo judges the override by its own
definition whatever that base holds: `class ShopPortal(PortalMixin, Shop)` with an undecorated
`orders` is reported when `Shop` comes from `Controller` and routes `orders`. A class none of whose
bases the scan reads is left out.

## Example

```python title="controllers/portal.py"
from odoo.addons.shop.controllers.main import Shop


class ShopPortal(Shop):
    def orders(self):
        response = super().orders()
        response.qcontext["title"] = "My orders"
        return response
```

`Shop.orders` routes `/shop/orders`; on 15.0 the override above serves nothing. Decorate it with an
empty `@route()`, which keeps the path and every other key of the route it overrides:

```python title="controllers/portal.py"
from odoo import http
from odoo.addons.shop.controllers.main import Shop


class ShopPortal(Shop):
    @http.route()
    def orders(self):
        response = super().orders()
        response.qcontext["title"] = "My orders"
        return response
```

## Suppressing

```python
def orders(self):  # odooscan: ignore[OD232]
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
