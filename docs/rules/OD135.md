# OD135 browse-in-loop

A loop over records browses one id at a time, so each record is fetched on its own.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Performance | Info | all | no |

## What it reports

A call to `browse()` in the body of a `for` loop over records, on a model the loop does not vary,
with one id that names what the loop binds: an `x.id` attribute, an `int()` call, or a list or tuple
of one item. The pass must read the record: an attribute or a method of the call's result, or of a
name assigned the result, alone or in an `or`, such as `journal.currency_id or ...browse(...)`. The
loop, its records and the cases it stays silent on are those of [OD134](OD134.md), except a keyed
search, which concerns a search alone.

A `browse()` of a name or of `ids`, such as `browse(order.line_ids.ids)`, of the same id on each
pass, or whose record is only stored, such as `rec.employee_id = ...browse(rec.id)`, is not
reported: a field holds the record without reading it, and the cache serves an id already fetched.

## Why it matters

`browse()` gives the records it returns their own ids alone to prefetch (18.0 `odoo/models.py`, 20.0
`odoo/orm/models.py`, `browse()`). Reading a field of a record browsed by itself fetches that record
alone, so the loop runs a query per record where records browsed together, or the records the id was
read from, would fetch them all in one.

## Example

```python title="models/sale_order.py"
class SaleOrder(models.Model):
    _inherit = "sale.order"

    def _x_currency_names(self):
        names = []
        for order in self:
            currency = self.env["res.currency"].browse(order.company_id.currency_id.id)
            names.append(currency.name)
        return names
```
