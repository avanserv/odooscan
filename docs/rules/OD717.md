# OD717 sudo-public-attachment

Data a user controls is stored in an attachment anyone may download.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Security | Warning | all | no |

## What it reports

A `create()` of `ir.attachment` under `sudo()`, or in another way that runs as superuser, whose
values set `public` to `True` and store content from a source, as [the OD7
rules](https://avanserv.github.io/odooscan/rules/#od7-data-flows) define both, in the key `raw`,
`db_datas`, or `datas` before saas~19.3 and in a module whose series is unknown. So does
`_upload_file(file, create_vals)`, whose file is content too. The values are a dict literal,
`dict(...)`, a list or a tuple of them, or a local bound to one, with keys set as `vals["raw"] = x`
or merged as `vals |= {...}`; `{**post}` and `dict(post)` add any key of a mapping the user sent,
and so do `post["public"] = True` and `post |= {...}` on a local holding one or its `copy()`. Each
dict of a list is its own attachment, so one dict must set both `public` and the content. A key of
the content set again on every path replaces what it held, so `vals["raw"] = logo` after `raw` took
the upload stores the logo. A method that stores its parameter this way is reported when a route
passes it what the user sent.

A create with the rights of the user, as a plain `create()`, one after `with_user()` for a user
other than the superuser or after a later `sudo(False)` (on records other than the superuser's, or
any before saas~12.5), is reported too where the modules the scan reads for the module grant portal
or public users create on `ir.attachment`, by an `ir.model.access` or `ir.access` row such as
[OD402](OD402.md) reports. Their uploads then reach a public attachment as they would under
`sudo()`. Odoo lets those rows decide before saas~13.1 and from 19.0 (19.0
`odoo/addons/base/models/ir_attachment.py:780-818`). Before saas~13.1 Odoo grants portal users
create on `ir.attachment` itself (`base` from 11.0, `portal` on 9.0 and 10.0), so a module there is
reported without a row of its own. A module whose series is unknown is read as the newest series
and is reported. This part needs `base` in the scan, whose rows tell whether any row grants it.

Not reported: a create with the rights of the user where no row grants portal or public users
create on `ir.attachment`, or from saas~13.1 to saas~18.4, where Odoo refuses it to any user but an
internal one whatever the rows (18.0 `odoo/addons/base/models/ir_attachment.py:472-473`), as an
internal user may set `public` anyway; such a create of what an RPC argument holds, as a client
granted the create may call `create()` itself; a `public` the code computes rather than writes as
`True`; values whose content the code picks, even when the user picks the `name` or the `res_id`;
and a helper setting `public` on the values its caller passes, whose keys the caller picks.

## Why it matters

`/web/content/<id>` serves a public attachment without a read check (18.0
`odoo/addons/base/models/ir_attachment.py:741`, through
`odoo/addons/base/models/ir_binary.py:54-56`), so anyone who has the id gets it, and ids count up.
A file a customer sends for one ticket or one order, such as a signed contract or an identity card,
is then there for whoever counts the ids. The user sent the content, which is why the rule warns
rather than errors.

## Example

```python title="controllers/main.py"
class TicketController(http.Controller):
    @http.route("/ticket/<int:ticket_id>/upload", type="http", auth="public", methods=["POST"])
    def upload(self, ticket_id, document):
        request.env["ir.attachment"].sudo().create({
            "name": document.filename,
            "raw": document.read(),
            "res_model": "helpdesk.ticket",
            "res_id": ticket_id,
            "public": True,
        })
        return request.redirect(f"/ticket/{ticket_id}")
```

Anyone downloads the document once they find its id.

```python title="controllers/main.py"
class TicketController(http.Controller):
    @http.route("/ticket/<int:ticket_id>/upload", type="http", auth="public", methods=["POST"])
    def upload(self, ticket_id, document):
        attachment = request.env["ir.attachment"].sudo().create({
            "name": document.filename,
            "raw": document.read(),
            "res_model": "helpdesk.ticket",
            "res_id": ticket_id,
        })
        token = attachment.generate_access_token()[0]
        return request.redirect(f"/web/content/{attachment.id}?access_token={token}")
```

## Suppressing

```python
request.env["ir.attachment"].sudo().create(vals)  # odooscan: ignore[OD717]
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
