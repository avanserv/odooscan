# OD717 sudo-public-attachment

Data a user controls is stored as superuser in an attachment anyone may download.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Security | Warning | all | no |

## What it reports

A `create()` of `ir.attachment` under `sudo()`, or in another way that
[runs as superuser](https://avanserv.github.io/odooscan/rules/#od7-data-flows), whose values set
`public` to `True` and store content from a
[source](https://avanserv.github.io/odooscan/rules/#od7-data-flows): the key `raw`, `db_datas`,
or `datas` before saas~19.3 and in a module whose series is unknown. So does
`_upload_file(file, create_vals)`, whose file is content too. The values are a dict literal,
`dict(...)`, a list or a tuple of them, or a local bound to one, with keys set as
`vals["raw"] = x` or merged as `vals |= {...}`; `{**post}` and `dict(post)` add any key of a
mapping the user sent, and so do `post["public"] = True` and `post |= {...}` on a local holding
one or its `copy()`. Each dict of a list is its own attachment, so one dict must set both `public`
and the content. A key of the content set again on every path replaces what it held, so
`vals["raw"] = logo` after `raw` took the upload stores the logo. A method that stores its
parameter this way is reported when a route passes it what the user sent.

Not reported: a create that does not run as superuser, as after a later `sudo(False)` on records
other than the superuser's, or `with_user()` for a user other than the superuser, which runs with
the rights of a user who may set `public` anyway; a `public` the code computes rather than writes
as `True`; values whose content the code picks, even when the user picks the `name` or the
`res_id`; and a helper setting `public` on the values its caller passes, whose keys the caller
picks.

## Why it matters

A public attachment skips the read check (18.0 `odoo/addons/base/models/ir_attachment.py:481`), so
`/web/content/<id>` serves it to anyone who has the id, and ids count up. A file a customer sends
for one ticket or one order, such as a signed contract or an identity card, is then there for
whoever counts the ids. The user sent the content, which is why the rule warns rather than errors.

## Example

```python title="controllers/main.py"
class TicketController(http.Controller):
    @http.route("/ticket/<int:ticket_id>/upload", type="http", auth="public", methods=["POST"])
    def upload(self, ticket_id, document):
        request.env["ir.attachment"].sudo().create({
            "name": document.filename,
            "raw": document.read(),
            "res_model": "helpdesk.ticket",
            "res_id": ticket_id,
            "public": True,
        })
        return request.redirect(f"/ticket/{ticket_id}")
```

Anyone downloads the document once they find its id.

```python title="controllers/main.py"
class TicketController(http.Controller):
    @http.route("/ticket/<int:ticket_id>/upload", type="http", auth="public", methods=["POST"])
    def upload(self, ticket_id, document):
        attachment = request.env["ir.attachment"].sudo().create({
            "name": document.filename,
            "raw": document.read(),
            "res_model": "helpdesk.ticket",
            "res_id": ticket_id,
        })
        token = attachment.generate_access_token()[0]
        return request.redirect(f"/web/content/{attachment.id}?access_token={token}")
```

## Suppressing

```python
request.env["ir.attachment"].sudo().create(vals)  # odooscan: ignore[OD717]
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
