# OD615 missing-component-prop

A template leaves out a prop a component's static props require.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Correctness | Error | 17.0 and later, before saas~19.4 | yes |

## What it reports

A component tag in a bundled template under `static/src` that leaves out props the component's
`static props` require, once per tag, naming them. A prop is required unless it is listed as
`"name?"`, or described by an object whose `optional` is anything but a literal `false`, as in
`{ type: String, optional: true }`, or that holds a spread, as in `{ ...base }`, which may give it
`optional`. A tag with children passes them as the `slots` prop.

Tags, the classes that render the template and the props are read as for [OD614](OD614.md), and
the rule is silent where OD614 is. It is silent too for a tag with `t-props`, which passes props
only a run tells, and for a template that an extension, or the template itself, gives
`position="attributes"` specs, which may set the prop.

## Why it matters

Owl checks the props a template passes a component against its `static props` in dev mode, which
Odoo turns on in debug mode and in its tests, and throws `Invalid props for component 'Card':
'title' is missing`, so the screen fails to render for anyone who activates the developer mode.
Outside it, the component reads `undefined` and may throw later. Owl refuses a `defaultProps`
value for a required prop, so a default does not make a prop optional. Owl 3, from saas~19.4, no
longer validates props.

## Example

```js title="static/src/order_card.js"
import { Component } from "@odoo/owl";

export class Card extends Component {
    static template = "sale_card.Card";
    static props = { title: String, subtitle: { type: String, optional: true } };
}

export class OrderCard extends Component {
    static template = "sale_card.OrderCard";
    static components = { Card };
}
```

```xml title="static/src/order_card.xml"
<templates>
    <t t-name="sale_card.Card"><h3 t-esc="props.title"/></t>
    <t t-name="sale_card.OrderCard">
        <Card subtitle="'Draft'"/>
    </t>
</templates>
```

`Card` requires `title`, so the template passes it.

```xml title="static/src/order_card.xml"
<templates>
    <t t-name="sale_card.Card"><h3 t-esc="props.title"/></t>
    <t t-name="sale_card.OrderCard">
        <Card title="'Order'" subtitle="'Draft'"/>
    </t>
</templates>
```

## Suppressing

```xml
<!-- odooscan: ignore[OD615] -->
<Card subtitle="'Draft'"/>
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
