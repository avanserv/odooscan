# OD216 selection-add-without-ondelete

`selection_add` leaves a value of a required `Selection` with `ondelete` `'set null'`.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Correctness | Error | 14.0 and later | yes |

## What it reports

A definition of a required `Selection` whose `selection_add` adds a value the field does not have
yet without giving it an `ondelete` policy, or that adds one and gives any value the policy
`'set null'`. The values the field has are those of its `selection` and of the `selection_add` of
every definition in the dependencies, in the class that introduces the model, and earlier in the
same file. Modules of earlier series are not checked.

## Why it matters

When a module that adds values to a selection is uninstalled, Odoo applies each value's `ondelete`
policy to the records that hold it, and a value without one gets `'set null'`. A required field
cannot be emptied, so Odoo refuses the definition when it sets up the model. The error stops the
registry from loading: the module cannot be installed, and a database that has it does not start.
Give each added value `'cascade'`, `'set default'` when the field has a default, or a function that
receives the records holding the value.

A `selection_add` that only reorders values the field has is not reported, even when it gives one of
them `'set null'`: Odoo only checks a definition that adds a value. When the field's values are
computed, a definition that sets them may come before or after this one, `required` is not a literal
or is unknown, or a definition unpacks `**kwargs`, the field is not reported. An attribute takes its
value from the last definitions that set it, and is unknown when those disagree, as two definitions
in different files of one module may: files load in the order of the imports, which is not indexed.

The rule does not run for a module when the module or one of its dependencies depends on a
module that is not indexed. A model is skipped when the class that introduces it with `_name` is in
a module outside the dependencies, or when a class of it, or of a model it inherits or delegates
to, has a plain Python base class, whose fields only Python knows.

## Example

```python title="models/parcel_route.py"
class ParcelRoute(models.Model):
    _name = "parcel.route"
    _description = "Parcel route"

    state = fields.Selection([("draft", "Draft"), ("done", "Done")], required=True, default="draft")


class ParcelRouteExpress(models.Model):
    _inherit = "parcel.route"

    state = fields.Selection(selection_add=[("express", "Express")])
```

`state` is required, so the value `express` needs a policy other than `'set null'`.

```python title="models/parcel_route.py"
class ParcelRouteExpress(models.Model):
    _inherit = "parcel.route"

    state = fields.Selection(
        selection_add=[("express", "Express")],
        ondelete={"express": "set default"},
    )
```

## Suppressing

```python
state = fields.Selection(selection_add=[("express", "Express")])  # odooscan: ignore[OD216]
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
