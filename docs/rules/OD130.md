# OD130 session-user-switch

Code switches the user a request or a session runs as.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Security | Info | all | no |

## What it reports

A call of `update_env()` with a user, an assignment to `request.session.uid` or
`request.session['uid']`, before 16.0 an assignment to `request.uid`, and an override of an
`_auth_method_*()` method in a class that inherits `ir.http`. A user of `None` keeps the one the
request has, and `request.session.uid` restores the one Odoo checked the session of before the route
ran, so neither is reported. Code inside any `_auth_method_*()` method, whose purpose is to set the
user, is not reported line by line; only an override on `ir.http` is, at its name. Code inside an
override of `update_env()` itself, which passes on the user its caller gives, is reported through
that caller. The public user counts like any other: switching to it hands the request the public
user's rights. This is a hotspot: code to review, not a confirmed flaw.

## Why it matters

`request.update_env(user=...)` runs the rest of the request as that user, with their access rights,
and the `uid` of the session decides which user every later request of the browser runs as. Odoo
picks the user of a route through `ir.http._auth_method_<auth>()`, so an override of one decides it
for every route with that `auth`. Each is correct only when the code has first proven that the
caller is that user, by a password, an API key or a signed token it checked. A value taken from the
request without that proof lets anyone act as anyone.

## Example

```python title="controllers/main.py"
class KioskController(http.Controller):
    @http.route("/kiosk/sign_in", type="json", auth="public", methods=["POST"])
    def sign_in(self, employee_id):
        employee = request.env["hr.employee"].sudo().browse(int(employee_id))
        request.update_env(user=employee.user_id.id)
        return {"name": request.env.user.name}
```

Any visitor who posts an employee id runs as that employee's user.

```python title="controllers/main.py"
class KioskController(http.Controller):
    @http.route("/kiosk/sign_in", type="json", auth="public", methods=["POST"])
    def sign_in(self, login, password):
        credential = {"login": login, "password": password, "type": "password"}
        request.session.authenticate(request.db, credential)
        return {"name": request.env.user.name}
```

The visitor proves who they are with a password, and Odoo signs them in. The example is 18.0's:
`authenticate()` takes `(env, credential)` from 19.0, and is a function of `odoo.http.session` taking
`(session, env, credential)` from 20.0.

## Suppressing

```python
request.update_env(user=employee.user_id.id)  # odooscan: ignore[OD130]
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
