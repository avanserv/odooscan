# OD710 xml-entity-flow

Data a user controls is parsed as XML by a parser that resolves entities.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Security | Warning | all | no |

## What it reports

A value from a [source](https://avanserv.github.io/odooscan/rules/#od7-data-flows) that reaches
`etree.fromstring()`, `etree.XML()`, `etree.parse()` or `objectify.fromstring()` of lxml with a
parser that resolves entities: one built by `etree.XMLParser(resolve_entities=True)`, passed
inline or through a local.

Before saas~19.1 the default parser resolves them too, and so does an `XMLParser()` built without
`resolve_entities`: on Python 3.11 and earlier those series run on lxml 4, whose default it is.
Odoo sets a default parser that resolves none, but for the thread that loads `odoo.tools` only.
The workers of a server with `workers` above 0 serve requests in that thread, so the finding holds
for a threaded server, with `workers = 0`, whose requests parse with lxml's default. From saas~19.1
Odoo needs Python 3.12 and lxml 5, whose default resolves no external entity, and those calls are
not reported. Neither is an unknown series, read as the newest.

A file from `file_open()` lies under the addons paths, so it is not the user's.

## Why it matters

An external entity names a file or a URL, and the parser puts what it reads there in the document:
`<!ENTITY x SYSTEM "file:///etc/odoo/odoo.conf">` hands the user the configuration file with the
database password when the parsed text shows up in a reply or an error. The rule warns rather than
errors because the default parser, behind most findings, resolves entities only on Python 3.11 and
earlier.

## Example

```python title="controllers/main.py"
from lxml import etree


class Feed(http.Controller):
    @http.route("/shop/feed/import", type="http", auth="user", methods=["POST"])
    def import_feed(self, feed):
        root = etree.fromstring(feed.encode())
        return request.make_response(root.findtext("title"))
```

On 18.0, run on Python 3.11 or earlier by a server with `workers = 0`, lxml resolves the entities
of `feed`, so its title may hold any file of the server. From saas~19.1 the example reports
nothing.

```python title="controllers/main.py"
from lxml import etree


class Feed(http.Controller):
    @http.route("/shop/feed/import", type="http", auth="user", methods=["POST"])
    def import_feed(self, feed):
        parser = etree.XMLParser(resolve_entities=False)
        root = etree.fromstring(feed.encode(), parser)
        return request.make_response(root.findtext("title"))
```

The parser keeps the entities as they are and reads no file.

## Suppressing

```python
root = etree.fromstring(text)  # odooscan: ignore[OD710]
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
