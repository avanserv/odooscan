# OD201 unknown-model

The model is not defined by any indexed module.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Correctness | Error | all | yes |

## What it reports

A model name that no module on the addons path defines, where Odoo needs the model to exist: a
parent in `_inherit`, the comodel of a `Many2one`, `One2many` or `Many2many`, the `model` of a
view, the `model` of a `<record>` in a data file, the model a data CSV is named after, and the
`res_model` of a window action, as a `<record>` or an `<act_window>` gives it literally. Those
places are all it reads. A `<function>` on an unknown model stops its file from loading too, but
neither this rule, [OD202](OD202.md) nor [OD314](OD314.md) reports it. A model that another
indexed module defines, but that module is missing from `depends`, is [OD202](OD202.md) instead.

## Why it matters

Odoo builds a model on top of every parent in `_inherit` and raises `TypeError` when one is not in
the registry, so the module cannot be installed and a database that already has it fails to
start. A view whose model does not exist fails validation, and a `<record>` of an unknown model,
or a data CSV named after one, stops its file from loading; either aborts the install. A
relational field is the quiet case: Odoo logs a warning and points the field at a placeholder
model, so it never holds a record. A window action on an unknown model fails when a user opens it.

Most findings are typos or models renamed between versions. A model from a module that is not on
the addons path, such as an Enterprise module, is reported too: add that module's directory to
the addons path rather than suppressing the finding. A `<record>` or data CSV of a module whose
dependencies include one that is not indexed gets no finding, because that dependency may define
the model. A module whose classes build `_name` from an expression gets no finding, because the
models it defines cannot be listed before it runs.

## Example

```python title="models/sale_order_line.py"
class SaleOrderLine(models.Model):
    _inherit = "sale.order.lines"

    partner_tag_ids = fields.Many2many("res.partner.categories")
```

The model is `sale.order.line`, and partner tags are `res.partner.category`.

```python title="models/sale_order_line.py"
class SaleOrderLine(models.Model):
    _inherit = "sale.order.line"

    partner_tag_ids = fields.Many2many("res.partner.category")
```

## Suppressing

```python
partner_tag_ids = fields.Many2many("x_partner_tag")  # odooscan: ignore[OD201]
```

For a data CSV, where a comment would break the file, pass `--ignore OD201` or add it to `ignore`
in the configuration file.

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
