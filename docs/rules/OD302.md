# OD302 xmlid-not-in-depends

The XML id comes from a module missing from depends.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Correctness | Error | all | yes |

## What it reports

A reference to an XML id defined by a module that is not among the referencing module's
dependencies, direct or transitive. The references checked are the same as for
[OD301](OD301.md): `ref` attributes and the other references in data files, and `env.ref()` in
Python. In a data file it also reports an id whose module is neither in `depends` nor on the
addons path. A module that Odoo always installs with `base`, such as `web`, counts as in
`depends`.

## Why it matters

Odoo loads modules in the order their `depends` set. A module that names another's id without
depending on it works in a database where that module happens to be installed and loaded first,
and fails in one where it is not: the data file stops the install with "External ID not found in
the system", and `env.ref()` raises `ValueError` when the line runs. Tests in a full database pass,
and the failure shows up on a customer's lean one.

In Python, only ids of indexed modules are checked, because code often names an Enterprise or
optional module's id behind a check that the module is installed. Groups given to `has_group()`
or a field's `groups` are not reported here, for the same reason. Upgrade scripts under
`migrations/` and `upgrades/` are skipped, since they name ids of past versions.

## Example

```python title="models/sale_order.py"
class SaleOrder(models.Model):
    _inherit = "sale.order"

    def _rush_picking_type(self):
        return self.env.ref("stock.picking_type_out")
```

The module depends on `sale` only, and `sale` does not depend on `stock`, so the id exists only
when some other module has installed `stock`.

```python title="__manifest__.py"
{
    "name": "Rush delivery",
    "version": "18.0.1.0.0",
    "depends": ["sale_stock"],
}
```

`sale_stock` depends on both `sale` and `stock`. When no such module fits, list the module that
defines the id in `depends` yourself.

## Suppressing

```python
return self.env.ref("stock.picking_type_out")  # odooscan: ignore[OD302]
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
