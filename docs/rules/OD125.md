# OD125 python-api-deprecated

The module uses a Python API its series deprecates.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Deprecation | Warning | saas~12.5 and later | no |

## What it reports

A form of the Python API that Odoo warns about in the module's series and still runs, from the
series in the second column until the one where [OD126](OD126.md) takes over:

| Form | Deprecated from | Removed or ignored from | Use instead |
| --- | --- | --- | --- |
| field option `track_visibility=` | saas~13.4 | saas~18.1 | `tracking=` |
| `sudo(user)` | saas~12.5 | saas~15.3 | `with_user(user)` |
| `flush()`, `recompute()` on a recordset | saas~15.4 | saas~16.2 | `flush_model()`, `flush_recordset()` or `self.env.flush_all()` |
| `invalidate_cache()` on a recordset | saas~15.4 | saas~16.2 | `invalidate_model()`, `invalidate_recordset()` or `self.env.invalidate_all()` |
| `refresh()` on a recordset | saas~15.2 | saas~16.2 | `invalidate_recordset()`, `invalidate_cache()` before saas~15.4 |
| `check_access_rights()`, `check_access_rule()` | 18.0 | saas~19.1 | `check_access()` |
| `read_group()` | saas~18.2 | saas~19.1, before 20.0 | `_read_group()` |
| an import of `odoo.osv` | 19.0 | saas~19.1 | `odoo.fields.Domain` |
| `@route(type='json')` | saas~18.1 | none | `type='jsonrpc'` |

`sudo()` counts as given a user when its argument is an integer, a `ref()` or `browse()` call
with or without `.id`, or a name whose last word is `user` or `uid`, before any `id`, or
`superuser` with the `id`, such as `user`, `self.env.uid`, `admin_user.id` or `SUPERUSER_ID`. A
flag such as `self.env.su`, `is_superuser`, `as_superuser` or `self.user_can_edit` is not a user.
`flush()`, `recompute()`, `invalidate_cache()` and `refresh()` are reported only on `self` in a
model class that does not define the method, and on a model the code names, such as
`self.env["res.partner"]`, since cursors, files and browsers have methods of these names. An
import is reported once per statement, wherever it sits, so an import inside a function counts
too.

## Why it matters

Each form still works in the series that deprecates it, and logs a `DeprecationWarning` or a
warning in the server log. A later series removes it, or keeps accepting it and does nothing with
it, and the module then fails or quietly loses the behaviour: the table gives that series, from
which OD126 reports the same form as an error. `type='json'` is an alias of `jsonrpc`, and the
table gives no removal series for it.

The 20.0 `read_group()` is another method with the name of the old one, so a call of it on 20.0 is
not reported here. [OD126](OD126.md) reports one that passes `fields=`, `orderby=` or `lazy=`.

## Example

```python title="models/sale_order.py"
class SaleOrder(models.Model):
    _inherit = "sale.order"

    def _confirm_as(self, user):
        self.check_access_rights("write")
        return self.with_user(user).action_confirm()
```

On 18.0, `check_access_rights()` warns on every call, and saas~19.1 no longer has it.

```python title="models/sale_order.py"
class SaleOrder(models.Model):
    _inherit = "sale.order"

    def _confirm_as(self, user):
        self.check_access("write")
        return self.with_user(user).action_confirm()
```

## Suppressing

```python
self.check_access_rights("write")  # odooscan: ignore[OD125]
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
