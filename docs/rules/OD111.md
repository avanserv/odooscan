# OD111 public-route-sudo

A public or `auth='none'` route runs as superuser.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Security | Info | all | no |

## What it reports

A controller method whose `@http.route` sets `auth="public"` or `auth="none"` and whose body calls
`sudo()`, or builds an environment for the superuser: `with_user()`, `env(user=...)`,
`update_env(user=...)` or `api.Environment(cr, uid, ...)` given `SUPERUSER_ID` or `1`, or `env()`,
`update_env()` or `api.Environment()` given `su=True`. Before 16.0 it also reports
`request.uid = SUPERUSER_ID`, which rebuilds `request.env` for that user; from 16.0 the assignment
raises. Odoo runs uid 1 in superuser mode whatever `su` says. `sudo(False)`, which leaves superuser
mode, is not reported. This is a hotspot: code to review, not a confirmed flaw.

An override that leaves `auth` out keeps that of the route it overrides, so a bare
`@http.route()` over a public route is reported too, when the scan reads the class it extends:
one an `odoo.addons` import names, or one defined above it in the same file.

## Why it matters

A public route answers anyone, signed in or not; `auth="none"` runs without any user. Superuser mode
lifts access rights and record rules, so from that point the code alone decides what the visitor
may read or change. When a record id, a domain or values come from the URL or the form, the route
must check that the visitor is entitled to that record, for example with an access token, or anyone
can walk through the ids and read or modify every record. Many public routes use `sudo()`
correctly; the finding asks for that check to be confirmed.

Routes with `auth="user"`, the default, are not reported: Odoo's access rights still apply to the
signed-in user until the code calls `sudo()`. Only the route's own body is read, with the
functions it nests, so a `sudo()` in a helper it calls is not reported.

## Example

```python title="controllers/main.py"
class WarrantyController(http.Controller):
    @http.route("/warranty/claims", type="http", auth="public", website=True)
    def warranty_claims(self, email):
        claims = request.env["warranty.claim"].sudo().search([("email", "=", email)])
        return request.render("warranty_portal.claims_page", {"claims": claims})
```

Any visitor who knows a customer's email can open `/warranty/claims?email=...` and read their
claims.

```python title="controllers/main.py"
class WarrantyController(http.Controller):
    @http.route("/warranty/claims", type="http", auth="user", website=True)
    def warranty_claims(self):
        partner = request.env.user.partner_id
        claims = request.env["warranty.claim"].search([("partner_id", "=", partner.id)])
        return request.render("warranty_portal.claims_page", {"claims": claims})
```

The route asks the visitor to sign in and reads as them, so their access rights and record rules
decide which claims they see. A route that must stay public checks the record's access token
instead, as `_document_check_access()` of the portal does; [OD716](OD716.md) reports one that
returns records by id without it.

## Suppressing

```python
def warranty_claims(self, email):  # odooscan: ignore[OD111]
```
