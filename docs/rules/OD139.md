# OD139 search-first-without-limit

search() without a limit fetches every match to keep the first.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Performance | Warning | all | no |

## What it reports

`[0]` or `[:1]` of a `search()` call on records with no `limit`, such as
`self.env["res.country"].search([("code", "=", code)])[0]`. Records are those of [OD138](OD138.md).
A `search()` given a `limit`, by keyword or as its third argument, is not reported, nor one on an
attribute or on a name last bound to one, such as `pattern = self.EMAIL_RE` then
`pattern.search(text)[0]`.

## Why it matters

`search()` with no limit selects the id of every matching row (18.0 `odoo/models.py`, 20.0
`odoo/orm/models.py`, `search()`), and `[0]` keeps one of them (`__getitem__()`). With `limit=1` the
database stops at the first row, in the same order. `[:1]` then keeps the empty recordset when
nothing matches, where `[0]` raises an `IndexError`.

## Example

```python title="models/sale_order.py"
class SaleOrder(models.Model):
    _inherit = "sale.order"

    def _x_default_warehouse(self):
        return self.env["stock.warehouse"].search([("company_id", "=", self.company_id.id)])[:1]
```

```python title="models/sale_order.py"
class SaleOrder(models.Model):
    _inherit = "sale.order"

    def _x_default_warehouse(self):
        return self.env["stock.warehouse"].search([("company_id", "=", self.company_id.id)], limit=1)
```

## Suppressing

```python
self.env["stock.warehouse"].search(domain)[:1]  # odooscan: ignore[OD139]
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
