# OD804 template-missing-message

A message a module's Python marks for translation is missing from its .pot template.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Quality | Info | all | no |

## What it reports

A call of `_()`, `_lt()` or `env._()` in a `.py` file of a module that has an `i18n/<module>.pot`
template, whose message the template holds in no entry `_()` reads: one with a `code:` reference
and the `odoo-python` comment, or with no comment that tells Python from the web client, as older
exports write. The finding sits on the first call of each message, and says whether the template
lacks the message or holds it only for records or the web client.

Only a call every extractor reads the same way is reported: its first argument is one or more
plain strings, and it sits outside an f-string and outside another `_()` call. The export stops
reading a file at a `_()` argument it fails on, and keeps the messages of the calls closed before
it, so the rule skips each call that closes at or after one: an argument of bytes; unless the
series is known to be saas~18.2 or later, an f-string with a replacement field other than a
string or an f-string of strings, such as `f"Shelf {name}"`, which Babel may fail to evaluate; and
unless the series is known to be before saas~18.2, an f-string such as `f"Close with }}"`, whose
doubled brace Odoo's extractor fails to read on Python 3.12 and later. The rule keeps only
messages every series exports: those with a letter, and at least two letters, digits or
underscores in all. `_lt()` counts in a module whose series is known to be saas~12.5 or later, the
first series whose export reads it.

## Why it matters

Translators work from the template: `odoo-bin i18n export` (20.0 `odoo/cli/i18n.py:220-227`)
writes every `_()` and `_lt()` message of the module's `.py` files into it (18.0
`odoo/tools/translate.py:1443-1447`), and the `.po` files of each language are merged from it. A
message the template lacks reaches no translation file, so every user reads it in the source
language. A template missing messages was exported before the code changed.

## Example

```python title="models/sale_order.py"
from odoo import _, models


class SaleOrder(models.Model):
    _inherit = "sale.order"

    def action_kiosk(self):
        return _("The kiosk is closed")
```

```po title="i18n/sale_kiosk.pot"
#. module: sale_kiosk
#: model:ir.model.fields,field_description:sale_kiosk.field_sale_order__x_kiosk_id
msgid "Kiosk"
msgstr ""
```

Export the template again, which adds the entry:

```po title="i18n/sale_kiosk.pot"
#. module: sale_kiosk
#. odoo-python
#: code:addons/sale_kiosk/models/sale_order.py:0
msgid "The kiosk is closed"
msgstr ""
```

## Suppressing

```python
return _("The kiosk is closed")  # odooscan: ignore[OD804]
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
