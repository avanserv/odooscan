# OD707 path-traversal-flow

Data a user controls picks the path of a file the server opens.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Security | Error | all | no |

## What it reports

A value from a [source](https://avanserv.github.io/odooscan/rules/#od7-data-flows) that reaches the
path of `open()` (bare or as `io.open()`, the same built-in on Python 3) or of `send_file()`, or any
argument of `os.path.join()`. `Image.open()` and other methods named `open` are not reported.
`file_open()` is not reported either: it opens a file only under the addons paths, so `../` cannot
leave them.

A value passed through `secure_filename()` is harmless for every rule, and one passed through
`os.path.basename()`, or wrapped in `io.BytesIO()` or `io.StringIO()`, for this one: a name
without its directories opens no other file, and a stream holds the data rather than names a file.

An `os.path.join()` assigned to a local, bare or inside `os.path.normpath()`, `os.path.realpath()`
or `os.path.abspath()`, is not reported when the normalized local is used only where a test of
`startswith(prefix)` holds: inside the `if` that tests it, after an `assert` of it, after an
`if not` of it that returns, raises or ends the loop's turn with `continue`, in the element of a
comprehension whose `if` tests it, alone or as an operand of an `and`, or in a later operand of an
`and` in the test of an `if`, `elif` or `assert`. An `and` anywhere else confines nothing. With
`..` resolved, the path stays under the prefix. A use before the test, or after an `if` whose arm
alone holds it, is reported, so a test that raises on a prefix it denies confines nothing.

Each prefix must be one the code picks, a literal or a value the user sets nothing of, and more
than the root: `/`, an empty string and `os.sep` do not count. A prefix that `os.path.join()`
builds from a user value is the user's, even when the value passes through `os.path.basename()`.
A prefix without a trailing separator counts, though `/srv/docs` admits `/srv/docs2`.

The `name` of a file read from `request.httprequest.files` by a field the code names, with `get()`,
`getlist()` or an item, is that field, so it is not reported, in the method or in a method the file
is passed to, as long as that method reads the `name` of the file itself rather than of an object
built from it, such as a `tarfile` member or the file's `stream`. Its `filename` is the user's.

## Why it matters

A path the user picks may climb out of the directory the code meant with `../`, or be absolute, in
which case `os.path.join()` drops everything before it. The server then reads or writes any file
its user can: the configuration file with the database password and the admin password, the
filestore of another database, or the source of the server.

## Example

```python title="controllers/main.py"
class Manuals(http.Controller):
    @http.route("/shop/manual", type="http", auth="user")
    def manual(self, name):
        path = os.path.join(MANUALS_DIR, name)
        return request.make_response(open(path, "rb").read())
```

`name` may be `../../../etc/odoo/odoo.conf`.

```python title="controllers/main.py"
class Manuals(http.Controller):
    @http.route("/shop/manual", type="http", auth="user")
    def manual(self, name):
        path = os.path.join(MANUALS_DIR, os.path.basename(name))
        return request.make_response(open(path, "rb").read())
```

`os.path.basename()` keeps the file name and drops the directories.

## Suppressing

```python
content = open(path, "rb").read()  # odooscan: ignore[OD707]
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
