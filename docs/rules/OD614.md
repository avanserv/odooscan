# OD614 unknown-component-prop

A template passes a component a prop its static props do not declare.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Correctness | Error | 17.0 and later, before saas~19.4 | yes |

## What it reports

Each attribute of a component tag in a bundled template under `static/src` that names no prop of
the component's `static props`, which declare no `*`. A component tag is an element whose tag does
not start with a lowercase letter, without `t-component`. Its props are its attributes that do not
start with `t-`, each cut at its first dot when a `bind`, `translate` or `alike` suffix follows, so
`onClose.bind` passes `onClose`. An attribute with another suffix is skipped, as Owl refuses it when
it compiles the template.

The tag is read against the classes that render the template: the loaded components outside
`static/tests` whose `static template` names it, and their subclasses that set no template of their
own. For an extension (`t-inherit-mode="extension"`), those of its parent. Each of them must name
the tag in its `static components`, its own or a parent's, and all of them the same class, whose
`static props` are then read, its own or a parent's. A `...Other.props` or `...super.props` spread
in them adds the props of that class.

The rule stays silent when a value only a run tells is on the way: a `static props` or `static
components` that is not a literal, a spread of anything else, or a write to either outside a
literal assignment, such as `Card.props.title = ...`, `Object.assign(Card.components, ...)` or
`patch(Card, { props })`, or a write into them through a subclass that declares none of its own. It is silent too for a template that another template calls with
`t-call`, or that a primary child inherits, as their elements render with other components, and
for a module whose dependencies include one that is not indexed, such as an Enterprise module.

## Why it matters

Owl checks the props a template passes a component against its `static props` in dev mode, which
Odoo turns on in debug mode and in its tests, and throws `Invalid props for component 'Card':
unknown key 'titel'`, so the screen fails to render for anyone who activates the developer mode.
Outside it, the value is silently lost, as the component reads its props by the declared names. A
port often meets this when a core component renames a prop. Owl 3, from saas~19.4, no longer
validates props.

## Example

```js title="static/src/order_card.js"
import { Component } from "@odoo/owl";

export class Card extends Component {
    static template = "sale_card.Card";
    static props = { title: String };
}

export class OrderCard extends Component {
    static template = "sale_card.OrderCard";
    static components = { Card };
}
```

```xml title="static/src/order_card.xml"
<templates>
    <t t-name="sale_card.Card"><h3 t-esc="props.title"/></t>
    <t t-name="sale_card.OrderCard">
        <Card titel="'Order'"/>
    </t>
</templates>
```

`Card` declares `title`, so the template passes it under that name.

```xml title="static/src/order_card.xml"
<templates>
    <t t-name="sale_card.Card"><h3 t-esc="props.title"/></t>
    <t t-name="sale_card.OrderCard">
        <Card title="'Order'"/>
    </t>
</templates>
```

## Suppressing

```xml
<!-- odooscan: ignore[OD614] -->
<Card titel="'Order'"/>
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
