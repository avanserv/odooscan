# OD505 qweb-key-ignored

The manifest lists templates under qweb, which Odoo ignores.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Deprecation | Warning | saas~14.3 and later | no |

## What it reports

A `qweb` key of the manifest that names a file no bundle giving templates lists. Only the bundles
of the module's own manifest count, so a file that another module's manifest adds to such a bundle
is still reported. A module often keeps the key beside the bundle that already loads the same
files, and those templates load, so the rule stays silent there.

Which bundles give templates depends on the series:

- Up to saas~14.4, `web.assets_qweb` alone.
- From saas~14.5, also `web.assets_frontend`, `mail.assets_discuss_public` and
  `project.assets_qweb`, whose pages fetch their templates.
- From saas~15.3, also `mrp_subcontracting.assets_qweb`.
- From 16.0, every bundle but `web.assets_qweb`.

Before 16.0 the `web.assets_frontend` fetch keeps only Owl templates, those with `owl="1"`. The
rule reads files, not templates, so a legacy template in such a file is not reported.

Before 16.0 the message asks for the bundle of the page that renders the templates, which is
`web.assets_qweb` for the web client. From 16.0 it names `web.assets_backend`.

## Why it matters

Up to saas~14.2 the web client fetches the templates of every file the `qweb` key lists. From
saas~14.3 nothing reads the key: a page fetches the templates of a bundle instead, and the web
client fetches those of `web.assets_qweb`. The module installs, but its client templates never
reach the browser: a widget or a dialog that renders one fails with a missing template. From 16.0
`web.assets_qweb` is not loaded either (see [OD506](OD506.md)), and a bundle such as
`web.assets_backend` carries the templates with its scripts.

Modules of saas~14.2 and earlier are not checked, since the key still loads there.

## Example

```python title="__manifest__.py"
{
    "name": "Library loans",
    "version": "15.0.1.0.0",
    "depends": ["web"],
    "qweb": ["static/src/xml/loan_badge.xml"],
    "license": "LGPL-3",
}
```

From saas~14.3 the badge template never reaches the browser, and the widget rendering it fails.
The widget runs in the web client, so list the file under `web.assets_qweb`:

```python title="__manifest__.py"
{
    "name": "Library loans",
    "version": "15.0.1.0.0",
    "depends": ["web"],
    "assets": {
        "web.assets_qweb": ["library_loan/static/src/xml/loan_badge.xml"],
    },
    "license": "LGPL-3",
}
```

## Suppressing

```python
"qweb": ["static/src/xml/loan_badge.xml"],  # odooscan: ignore[OD505]
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
