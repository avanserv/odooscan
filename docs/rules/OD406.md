# OD406 rule-without-permission

A record rule sets every perm_* false, which Odoo refuses as it loads it.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Correctness | Error | before saas~19.4 | yes |

## What it reports

A write to an `ir.rule`, in XML or CSV, after which `perm_read`, `perm_write`, `perm_create` and
`perm_unlink` are all false, by this write and the earlier writes to the record in scope. A
permission no write gives keeps its default, true. The rule's groups do not matter. A permission
only a run can tell, such as an `eval` that is no constant, keeps the rule silent.

A permission written as a string, as text or as a string `eval`, reads as the loader converts it.
From 10.0 it is false when it is `0`, `false` or `off` in any case, and true otherwise, `eval="''"`
included (18.0 `odoo/tools/convert.py:196-197,424-425`). An empty field is no string on 10.0 and
stores false; from 11.0 the loader reads it as the empty string, so it is true (11.0
`odoo/tools/convert.py:152`). Before 10.0 the field stores the string's truth: any text is true,
and an empty field or `eval="''"` is false.

From saas~19.4 `ir.access` replaces `ir.rule`, and its `operation` cannot be empty, so the rule
does not run.

## Why it matters

`ir.rule` carries the SQL constraint `no_access_rights`, a `CHECK` that one permission is true
(18.0 `odoo/addons/base/models/ir_rule.py:29-33`). The database refuses the row as the file writes
it, so the install or the update of the module fails. A rule that should restrict nothing has no
reason to exist; one meant to restrict some operations sets those true.

## Example

```xml title="security/rules.xml"
<record id="rule_stock_count_user" model="ir.rule">
    <field name="name">Own counts</field>
    <field name="model_id" ref="model_stock_count"/>
    <field name="domain_force">[('user_id', '=', user.id)]</field>
    <field name="perm_read" eval="False"/>
    <field name="perm_write" eval="False"/>
    <field name="perm_create" eval="False"/>
    <field name="perm_unlink" eval="False"/>
</record>
```

```xml title="security/rules.xml"
<record id="rule_stock_count_user" model="ir.rule">
    <field name="name">Own counts</field>
    <field name="model_id" ref="model_stock_count"/>
    <field name="domain_force">[('user_id', '=', user.id)]</field>
    <field name="perm_read" eval="False"/>
    <field name="perm_create" eval="False"/>
</record>
```

## Suppressing

```xml
<!-- odooscan: ignore[OD406] -->
```

For a CSV row, where a comment would break the file, pass `--ignore OD406` or record the finding
in a [baseline](https://avanserv.github.io/odooscan/baseline/).

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
