# OD330 unknown-view-widget

A view names a widget no script registers.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Correctness | Error | 17.0 and later | yes |

## What it reports

The `name` of a `<widget>` in a form, list or kanban view of a loaded data file, when no script of
the modules in scope adds the key to `registry.category("view_widgets")`. A key counts when a
loaded script outside `static/tests` adds it as a string literal, through
`registry.category("view_widgets").add("x", ...)`, a chain of `.add()` on it, or a binding of the
category. A key that only a module missing from `depends` registers is reported too, naming that
module. A module that Odoo always installs with `base`, such as `web`, or auto-installs with the
module, counts as in `depends`. The type of the view is the one at the root of its inheritance, and
a `<widget>` that a spec locates by is not read.

Modules before 17.0 are not checked: up to saas~16.4 a widget may sit in a legacy registry that the
web client bridges to this one. In a form of 17.0 or saas~17.1, a widget in a `div` with class
`oe_chatter` is not read either, since the form skips the children of that div there.

## Why it matters

The web client looks the widget up when it parses the arch and throws `Cannot find key "x" in the
"view_widgets" registry`, so the view does not open at all. Without the module that registers the
widget in `depends`, the view works only on a database where something else installed it.

The rule stays silent for a module whose dependencies include one that is not indexed, such as an
Enterprise module, and when a script in scope adds a key to the registry that only a run tells.

## Example

```xml title="views/sale_views.xml"
<record id="sale_order_form" model="ir.ui.view">
    <field name="model">sale.order</field>
    <field name="arch" type="xml">
        <form>
            <widget name="web_ribon" title="Cancelled" invisible="state != 'cancel'"/>
        </form>
    </field>
</record>
```

The widget is `web_ribbon`.

```xml title="views/sale_views.xml"
<record id="sale_order_form" model="ir.ui.view">
    <field name="model">sale.order</field>
    <field name="arch" type="xml">
        <form>
            <widget name="web_ribbon" title="Cancelled" invisible="state != 'cancel'"/>
        </form>
    </field>
</record>
```

## Suppressing

```xml
<!-- odooscan: ignore[OD330] -->
<widget name="web_ribon" title="Cancelled"/>
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
