# OD511 auto-install-not-depended

auto_install names a module missing from depends, so Odoo fails to read the manifest.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Correctness | Error | saas~12.4 and later | no |

## What it reports

An entry of an `auto_install` list that `depends` does not name. From saas~18.2, Odoo reads an
empty or missing `depends` as `["base"]` first, so a `base` entry there is reported only for a
module of an earlier series; every other entry is reported on every series the rule covers.

## Why it matters

From saas~12.4, `auto_install` takes the list of depends whose install installs the module, and
Odoo asserts that each is one of `depends` as it reads the manifest. A name outside it fails with
`auto_install triggers must be dependencies`: the module stays out of the apps list and cannot be
installed. Before saas~12.4 a list only switches `auto_install` on, waiting on every depend, so the
rule does not apply there.

## Example

```python title="__manifest__.py"
{
    "name": "Library loans for sales",
    "version": "18.0.1.0.0",
    "depends": ["sale"],
    "auto_install": ["sale", "library_loan"],
    "license": "LGPL-3",
}
```

`library_loan` is a trigger but not a dependency. Add it to `depends`:

```python title="__manifest__.py"
{
    "name": "Library loans for sales",
    "version": "18.0.1.0.0",
    "depends": ["sale", "library_loan"],
    "auto_install": ["sale", "library_loan"],
    "license": "LGPL-3",
}
```

## Suppressing

```python
"auto_install": ["sale", "library_loan"],  # odooscan: ignore[OD511]
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
