# OD332 unknown-tour

A test runs a tour no script registers.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Correctness | Error | 17.0 and later | yes |

## What it reports

A tour name that Python code gives `start_tour()`, as its second argument or `tour_name=`, when no
script of the indexed modules adds it to `registry.category("web_tour.tours")`. The call is skipped
when it passes `**` arguments or both `code=` and `ready=`, which replace what the name is used for.
The code and the ready check given to `browser_js()` as string literals count too, for each name
quoted as the whole argument of an `odoo.startTour()` or `odoo.isTourReady()` call in them. A test
that `@unittest.skip()` decorates, or whose class it decorates, is not read.

A key counts when a loaded script adds it as a string literal, through
`registry.category("web_tour.tours").add("x", ...)`, a chain of `.add()` on it, or a binding of the
category. Scripts under `static/tests` count, since test bundles such as `web.assets_tests` load
the tours, except in a unit test bundle such as `web.assets_unit_tests`, which runs on a page of
its own. A tour that only a module missing from `depends` registers is not reported: a test may
run it once it has skipped itself unless that module is installed.

Modules before 17.0 are not checked, as for the other rules that read registry keys.

## Why it matters

`start_tour()` waits for the tour to be ready before it starts it. For a tour that no script
registered, 17.0 and 18.0 throw in the browser and 20.0 never reports it ready, so the test fails
after its timeout without running a step. Tours are renamed with the features they test, which a
port leaves behind in the Python test.

The rule stays silent for a name built at run time, such as an f-string, for a module whose
dependencies include one that is not indexed, such as an Enterprise module, and when a script in
scope adds a key to the tours registry that only a run tells, as a helper given the tour name as an
argument does.

## Example

```python title="tests/test_ui.py"
from odoo.tests import HttpCase, tagged


@tagged("post_install", "-at_install")
class TestUi(HttpCase):
    def test_checkout(self):
        self.start_tour("/odoo", "sale_checkout_tuor", login="admin")
```

```js title="static/tests/tours/checkout.js"
registry.category("web_tour.tours").add("sale_checkout_tour", { steps: () => [] });
```

The script registers the tour under `sale_checkout_tour`.

```python title="tests/test_ui.py"
from odoo.tests import HttpCase, tagged


@tagged("post_install", "-at_install")
class TestUi(HttpCase):
    def test_checkout(self):
        self.start_tour("/odoo", "sale_checkout_tour", login="admin")
```

## Suppressing

```python
self.start_tour("/odoo", "sale_checkout_tuor")  # odooscan: ignore[OD332]
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
