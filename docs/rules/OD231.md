# OD231 route-path-shadowed

Two controllers declare the same route path, so one hides the other.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Correctness | Warning | all | yes |

## What it reports

A literal path in the `@route()` of a controller method that a method of another class declares
too, letter for letter, when:

- the other class is in the module or in a module it depends on, directly or not;
- neither class inherits the other;
- the two are not one method of classes Odoo merges into one controller, as two subclasses of one
  controller are, since that method is one endpoint;
- a request may reach both: the `methods` the two routes keep, merged with those of the routes they
  override, share one, or one of them takes every method.

Of two classes of one module, the later one is reported, by file and then by position; of two
modules, the one that depends on the other. The finding sits on the method's `def` and names the
other class, its method and its module.

## Why it matters

Odoo builds one controller of each class with `Controller` among its own bases, merged with all of
its subclasses, and adds a rule per path of each of their route methods to one routing map, for
every installed module. Two classes that both declare a path give that map two rules for it, and
only one of them answers a request: the other method never runs, and which one wins is werkzeug's
choice, not the code's. The usual cause is a module that means to change a route of another one
and declares a new controller instead of inheriting the one that serves it.

The rule leaves out:

- a class with a base the scan does not read, such as one a relative import or a library names,
  or one from a module that is not indexed, since it may be the other class's ancestor;
- a class that does not come from `odoo.http.Controller`, since Odoo builds no controller of it;
- a path built at runtime, and paths that differ only by a trailing slash or the name of a
  converter argument;
- request methods the scan cannot read;
- the controllers of `tests/`, `migrations/` and `upgrades/`;
- two modules neither of which depends on the other.

## Example

```python title="controllers/portal.py"
from odoo import http
from odoo.http import request


class ShopPortal(http.Controller):
    @http.route("/shop/orders", auth="user")
    def orders(self):
        return request.render("shop_portal.orders")
```

`shop` already routes `/shop/orders` in its own `Shop` controller, so one of the two pages is never
served. Inherit the class that routes the path and override its method:

```python title="controllers/portal.py"
from odoo import http
from odoo.addons.shop.controllers.main import Shop
from odoo.http import request


class ShopPortal(Shop):
    @http.route()
    def orders(self):
        return request.render("shop_portal.orders")
```

## Suppressing

```python
def orders(self):  # odooscan: ignore[OD231]
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
