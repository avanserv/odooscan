# OD509 version-refused

The manifest version has a form Odoo refuses, or names another series.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Correctness | Error | all | no |

## What it reports

A `version` that the Odoo of the scan's series will not install. That series is the one
`--target-series` or `--odoo-version` names, and the module's own when neither is given, so a
module whose version names another series is reported only under one of those flags.
`18.1.1.0.0` names saas~18.1, so it is reported with no flag.

From saas~16.3, Odoo takes two or three numbers, as in `1.0` or `1.2.3`, either alone or behind
the series, as in `18.0.1.0` or `18.0.1.0.0`. The rule reports:

- a part that is not a number, as in `1.0-beta` or `1.0.0rc1`;
- fewer than two parts, or more than five;
- four or five parts that do not start with the scan's series, as in `17.0.1.0.0` checked as 18.0,
  or `18.1.1.0.0` checked as saas~18.1, since a saas series is written `saas~18.1` at the head of
  a version.

The series alone (`18.0`) and the series with one number (`18.0.1`) are not reported: 18.0
takes the first and refuses the second, 20.0 the reverse. A module of unknown series gets only the
first two cases. Series before saas~16.3 take any version, so nothing is reported there.

## Why it matters

From saas~16.3 through 18.0, Odoo fails to read the manifest with `Invalid version`, so the module
stays out of the apps list. saas~18.1 fails to read the manifest on a malformed version with
`Invalid version`, and on four or five numbers not behind its series with `must have between 2
and 5 parts`. From saas~18.2 a malformed version still fails to read the manifest, and a version of
another series, or one behind a saas series written without `saas~`, marks the module
uninstallable with `has an incompatible version`. Either way the module never installs, and a
version that still names the previous series is the usual trace of a port that changed the code
but not the manifest.

## Example

```python title="__manifest__.py"
{
    "name": "Library loans",
    "version": "1.0-beta",
    "depends": ["base"],
    "license": "LGPL-3",
}
```

`1.0-beta` is not a number. Keep the numbers, behind the series if the module has one:

```python title="__manifest__.py"
{
    "name": "Library loans",
    "version": "18.0.1.0.0",
    "depends": ["base"],
    "license": "LGPL-3",
}
```

## Suppressing

```python
"version": "1.0-beta",  # odooscan: ignore[OD509]
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
