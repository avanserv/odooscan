# OD714 sudo-field-injection

Data a user controls picks the field read as superuser.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Security | Error | all | no |

## What it reports

A value from a [source](https://avanserv.github.io/odooscan/rules/#od7-data-flows) that names the
field read from records under `sudo()`, or from a local bound to them: the item of
`records.sudo()[name]`, the `fields` of `read()` and the `func` of `mapped()`.
[What runs as superuser](https://avanserv.github.io/odooscan/rules/#od7-data-flows) lists the
forms besides `sudo()`.

A test that the name is in `_fields`, as `if name not in records._fields: raise`, proves only that
the field exists: the user still picks which one. In the arm of `if field in self._PUBLIC:` the name
is one the code chose and is not reported; after the `if`, or in its `else`, it is. Records that do
not run as superuser are not reported, as the user's access rights and the groups of each field
bound what they read.

## Why it matters

`sudo()` lifts the access rights, the record rules and the groups of each field. A route meant to
show one field of a record then shows any: the private address or the bank account of an
employee, the token of a portal link, or a field only managers see.

## Example

```python title="controllers/main.py"
class Team(http.Controller):
    @http.route("/team/profile", type="json", auth="user")
    def profile(self, employee_id, field):
        employee = request.env["hr.employee"].sudo().browse(int(employee_id))
        return employee[field]
```

`field` may be `private_street` or `bank_account_id`.

```python title="controllers/main.py"
class Team(http.Controller):
    _PUBLIC = ("name", "job_title", "work_email")

    @http.route("/team/profile", type="json", auth="user")
    def profile(self, employee_id, field):
        if field not in self._PUBLIC:
            raise NotFound()
        employee = request.env["hr.employee"].browse(int(employee_id))
        employee.check_access("read")
        return employee.sudo()[field]
```

On 16.0 and 17.0, which have no `check_access()`, call `check_access_rights("read")` and
`check_access_rule("read")`.

## Suppressing

```python
return employee[field]  # odooscan: ignore[OD714]
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
