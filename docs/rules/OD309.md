# OD309 unknown-record-field

A data record sets a field its model does not have.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Correctness | Error | all | yes |

## What it reports

A `<field name="...">` of a `<record>`, or a column of a data CSV, that names no field of the
record's model, or a field that only a module missing from `depends` adds. A `name@fr` style
column sets a translation of `name`, and is read as `name`.

## Why it matters

Odoo creates or writes the record with the values the file gives, and the ORM refuses a key that
is not a field: the install stops with `Invalid field 'x' on model 'y'`. When the field comes from
a module outside `depends`, the file loads where that module is installed and fails where it is
not, or where it loads after this one.

A record on a model that no indexed module defines is reported once on the model by
[OD201](OD201.md), and its fields are not checked. A record on a model from a module outside
`depends` is reported here, on each field it sets.

## Example

```xml title="data/res_partner_category_data.xml"
<record id="tag_wholesale" model="res.partner.category">
    <field name="name">Wholesale</field>
    <field name="colour" eval="4"/>
</record>
```

The field on `res.partner.category` is spelled `color`.

```xml title="data/res_partner_category_data.xml"
<record id="tag_wholesale" model="res.partner.category">
    <field name="name">Wholesale</field>
    <field name="color" eval="4"/>
</record>
```

## Suppressing

```xml
<!-- odooscan: ignore[OD309] -->
```

For a CSV column, where a comment would break the file, pass `--ignore OD309` or add it to
`ignore` in the configuration file.

See [suppressing a finding](https://github.com/avanserv/odooscan#suppressing-a-finding).
