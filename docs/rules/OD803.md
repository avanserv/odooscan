# OD803 translation-empty

A translation file leaves messages untranslated, which Odoo shows in the source language.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Quality | Info | all | no |

## What it reports

A `.po` file in `i18n/` or `i18n_extra/` with entries whose translation is empty, once per file at
the first of them, with how many of its messages are untranslated and the line of each, such as
`(lines 47, 89)`. The text, `github` and `gitlab` formats name the first 20 lines and how many more
there are; `json` lists every one under `related`. `sarif` lists the first 1,000 as
`relatedLocations` and the count of the rest as `relatedLocationsOmitted`, a cap that follows
GitHub code scanning's limit of 1,000 locations per result, past which it rejects the whole file.
The header, obsolete entries and plural entries do not count. When the
folder holds the module's template, such as `i18n/sale_kiosk.pot`, an entry the template lacks is
obsolete, as Odoo merges the two before loading the catalog (18.0 `odoo/tools/translate.py:800-826`,
20.0 `:1381-1407`). A message of the template that the file lacks is not counted, as Odoo may fill
it from the file of a parent language, such as `es.po` for `es_CL.po` (18.0 `:1780-1793`, 20.0
`:2424-2432`). The template itself is not reported.

## Why it matters

Odoo skips an empty translation (18.0 `odoo/tools/translate.py:1527`, `:1837`; 20.0 `:2178`,
`:2622`), so users of the language read those messages as the module's source text, often in the
middle of translated ones. A file shipped half done is usually one a translation run missed after
new messages were added.

## Example

```po title="i18n/fr.po"
#. module: sale_kiosk
#: model:ir.model.fields,field_description:sale_kiosk.field_sale_order__x_kiosk_id
msgid "Kiosk"
msgstr ""
```

```po title="i18n/fr.po"
#. module: sale_kiosk
#: model:ir.model.fields,field_description:sale_kiosk.field_sale_order__x_kiosk_id
msgid "Kiosk"
msgstr "Kiosque"
```

## Suppressing

The finding sits on the first untranslated entry and its message holds the counts, so it moves
once that entry is translated, and a comment above it or a baseline stops covering it. The lines
of the other entries stay out of the message, so a baseline still covers the finding when they
move. Pass `--ignore OD803`, add it to `ignore` in the configuration file, or list the catalog in
`exclude`:

```toml
[tool.odooscan]
exclude = ["sale_kiosk/i18n/nl.po"]
```

See [suppressing a finding](https://avanserv.github.io/odooscan/suppressing/).
