# OD131 secret-compared-with-eq

A token, secret or signature is compared with == rather than consteq().

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Security | Warning | all | no |

## What it reports

A comparison with `==` or `!=` whose two operands both name a secret: the last word of the name,
the attribute, the literal key of a subscript or of `.get()`, or the called method is `token`,
`secret` or `signature`, as in `access_token`, `kw['token']`, `kw.get('signature')` or
`self._get_secret()`. A secret compared with anything else, such as `token_type == "bearer"`, is
not reported.

In the `write()` or an onchange of a model, a comparison that tells only whether a field changes is
not reported, since only a user who may set the field learns the answer. One is a field such as
`self.webhook_secret` against its value in the parameter named `vals` or `values`, else the second
one, as `vals['webhook_secret']` or `vals.get('webhook_secret')`. Another is a field compared with
the same field of any record, as before and after `super().write(vals)`, or on a record and on its
`_origin`, the stored record behind the new one of the form's values an onchange runs on, as
`rec.webhook_secret != rec._origin.webhook_secret`. Either side may be a local the method binds once
to such a value. In an onchange, `self.webhook_secret` or the same field of a record a loop takes
from `self`, against a local named `webhook_secret`, is not reported either. Any other comparison
there is reported, as is one in a function nested in them or in a `write()` outside a model.

Two signatures read from the same field, from the same function, or from the same method other than
`get()` given the same arguments, as `a.signature == b.signature`,
`get_signature(a) == get_signature(b)` or `a._get_signature() == b._get_signature()`, are not
reported: neither side is what a caller sends.

## Why it matters

`==` on strings stops at the first character that differs, so it takes longer the more of the
secret a guess gets right. A caller who can time the answers can find the secret one character at a
time. `hmac.compare_digest()` takes the same time whatever the inputs share, and so does
`consteq()` from `odoo.tools` (`openerp.tools` in 9.0): an alias of `hmac.compare_digest()` from
16.0, and passlib's version or a fallback of Odoo's own before it.

## Example

```python title="models/sale_order.py"
from odoo import models
from odoo.exceptions import AccessDenied


class SaleOrder(models.Model):
    _inherit = "sale.order"

    def _check_token(self, access_token):
        if access_token != self.access_token:
            raise AccessDenied()
```

```python title="models/sale_order.py"
from odoo import models
from odoo.exceptions import AccessDenied
from odoo.tools import consteq


class SaleOrder(models.Model):
    _inherit = "sale.order"

    def _check_token(self, access_token):
        if not consteq(access_token, self.access_token or ""):
            raise AccessDenied()
```

## Suppressing

```python
if access_token != self.access_token:  # odooscan: ignore[OD131]
```
