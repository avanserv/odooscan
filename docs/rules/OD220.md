# OD220 duplicate-field-label

Two fields of a model have the same label.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Correctness | Warning | all | yes |

## What it reports

A field whose label another field of the same model already has. The label is the literal `string`,
by keyword or by position, or for a field that gives none and is not related, the one Odoo derives
from its name: without a trailing `_ids` or `_id`, underscores made spaces, and each word
capitalized, so `partner_id` and `partner_ids` are both `Partner`. The fields Odoo adds to a model
count with their labels: `ID` and `Display Name`, `Last Modified on` (`__last_update`) until 16.0,
and on a model that logs access, `Created by`, `Created on`, `Last Updated by` and
`Last Updated on`. An abstract model has the first three until saas~14.3, so in 12.0 to 14.0,
none of them from saas~14.4 to 18.0, so in 15.0 to 18.0, and `ID` and `Display Name` from
saas~18.1, so from 19.0, where `BaseModel` defines them. A module of unknown series is checked as
one of saas~14.4 to 18.0, without `Last Modified on`, so no label is reported that its series may
lack.

The finding is at the definition in the module that decides the label: the last one that sets
`string`, or the field's first definition when the label is derived. A label is reported against
one that another module decides, or one that a definition this module loads earlier decides, so
each pair is reported once. When the two definitions are in different files of the module, the
order of the files in the module picks the one reported, since the order of the imports is not
indexed.

## Why it matters

When Odoo records a model's fields in `ir.model.fields`, it logs a warning for each field whose
label another field of the model already has. The label is what users see as the field's column,
filter and export name, so two fields with one label cannot be told apart. Give one of them another
`string`.

A label that is not a literal, such as `_lt("Notes")`, is unknown and never reported, nor is a
related field without `string`, which takes the label of the field it relates to, nor a field the
model gets through `_inherits`. The fields that log access are counted unless the model is
abstract, or a class of it sets `_auto` or `_log_access` to anything but `True`.

What a class that redefines one of the fields Odoo adds makes of its label depends on the series.
From saas~14.4, so from 15.0, the class merges into the field, which keeps the label Odoo gives it
unless a definition sets `string`. The class that introduces the model with `_name` is the exception
for every field but `id` and `__last_update`: Odoo does not add a field of a name that class
defines, so the class's own definition decides the label. Until saas~14.3, so in 12.0 to 14.0, Odoo
adds no field that a class of the model or of a model it inherits defines, so the definitions decide
the label, except for `id`, which keeps its label whatever a class sets. Until saas~12.4, so in
12.0, a definition without `string` also takes the label of the field Odoo added to a model the
model inherits: `Display Name` always, and the label of a field that logs access when that model
logs access. From saas~14.4, so from 15.0, or until saas~12.4, so in 12.0, when a model the model
inherits defines such a field too, its label is unknown and never reported. `Last Modified on`
always stands: Odoo adds `__last_update` whatever a class defines, and Python renames the name in a
class body (to `_`, the class name without its leading underscores, then the name), so no class
redefines it.

The rule does not run for a module when the module or one of its dependencies depends on a module
that is not indexed. A model is skipped when the class that introduces it with `_name` is in a
module outside the dependencies, or when a class of it, or of a model it inherits or delegates to,
has a plain Python base class, whose fields only Python knows. A module that Odoo always installs
with `base`, such as `web`, counts as in `depends`.

## Example

```python title="models/parcel_bag.py"
class ParcelBag(models.Model):
    _name = "parcel.bag"
    _description = "Parcel bag"

    partner_id = fields.Many2one("res.partner")
    partner_ids = fields.Many2many("res.partner")
```

```python title="models/parcel_bag.py"
class ParcelBag(models.Model):
    _name = "parcel.bag"
    _description = "Parcel bag"

    partner_id = fields.Many2one("res.partner")
    partner_ids = fields.Many2many("res.partner", string="Followers")
```

## Suppressing

```python
partner_ids = fields.Many2many("res.partner")  # odooscan: ignore[OD220]
```
