# OD211 orphan-super

`super()` calls a method no parent class defines.

| Category | Severity | Series | Needs the index |
| --- | --- | --- | --- |
| Correctness | Error | all | yes |

## What it reports

A `super().name()` call in a model class whose model, and the models it inherits, define no method
`name` in any other class, and which is not a method of `BaseModel` such as `create`, `write` or
`search`. Classes from modules outside `depends` count as parents here, because an override of a
method such a module adds is only called by that module.

## Why it matters

Python looks the method up along the model's classes when the call runs and raises
`AttributeError` when no class after this one has it. The usual cause is a method renamed or
removed upstream between versions: the override is then never called by Odoo, and calling it
directly fails.

The rule stays silent when it cannot see every parent: a class with a plain Python class among its
bases, a module whose dependencies include one that is not indexed (such as an Enterprise module),
a model no indexed module defines, and an abstract model, whose method may come from the models
that inherit it.

## Example

```python title="models/sale_order.py"
class SaleOrder(models.Model):
    _inherit = "sale.order"

    def _prepare_invoice_vals(self):
        vals = super()._prepare_invoice_vals()
        vals["narration"] = self.note
        return vals
```

`sale` names this method `_prepare_invoice`, so no parent has `_prepare_invoice_vals`.

```python title="models/sale_order.py"
class SaleOrder(models.Model):
    _inherit = "sale.order"

    def _prepare_invoice(self):
        vals = super()._prepare_invoice()
        vals["narration"] = self.note
        return vals
```

## Suppressing

```python
vals = super()._prepare_invoice_vals()  # odooscan: ignore[OD211]
```

See [suppressing a finding](https://github.com/avanserv/odooscan#suppressing-a-finding).
